# 최종 통합 검수 · Rhetis Spectrum

첨부 이미지 6개 덱 76장을 모두 구현했습니다. 원본 재현과 라이브러리 재조립은 동일한 1280×720 좌표계를 사용하며, 원본 이미지를 결과 슬라이드의 배경으로 사용하지 않습니다. 최종 제출용 렌더는 production 빌드에서 생성합니다.

## 범위와 계약

- 원본: 098의 17–23(7장), 101(10장), 103(10장), 104(19장), 105(10장), 106(20장).
- 입력 ZIP에 없는 덱이나 슬라이드는 추가하지 않았습니다.
- 첨부 README는 라이브러리 형식 계약으로 적용했습니다. 사용자 요청의 회색 placeholder, 1280×720, 실제 폰트 로드, 개별 브라우저 비교, 기존 파일 보존과 GitHub 제출 요구는 별도로 적용했습니다.
- 컬렉션 `rhetis-spectrum`: kit + page foundation + 31개 요소. 요소 fixture 87개, foundation fixture 2개, 각 모드 89개.
- 컬렉션 ZIP은 최상위 폴더가 `rhetis-spectrum/` 하나입니다.

## 개별 검수와 최종 확인

덱별 담당이 원본 전체를 한 장씩 읽고, Chromium 렌더를 원본과 개별 비교했습니다. 덱별 수정/비교는 2–3회 수행했습니다. 상세 기록은 d098.md, d101.md, d103.md, d104.md, d105.md, d106.md에 있습니다. 연락처 시트만으로 검수를 끝내지 않았습니다.

주 에이전트는 최종 source state와 production 렌더를 대조하고, 대표 복합 슬라이드의 원본/결과 및 재현/재조립 화면을 나란히 점검했습니다. 이 과정에서 조립기의 pill 라벨 DOM 연결 누락을 발견해 수정했습니다. 이후 전체 재조립 76장을 다시 렌더하고 빈 chip·문구 누락 검사도 추가했습니다. 106-18의 사진 아래에 가려진 중복 메타데이터도 제거했습니다. 모든 최종 렌더는 이 수정 이후 소스로 생성했습니다.

자동 검사는 폰트 가용성, JS 오류, 캔버스 크기, 실제 글리프 경계의 텍스트 잘림·영역 초과, chip 광학 중심, 원본 chip 문구 보존, 래스터 임베딩 여부, placeholder 색을 검사합니다. 최종 결과는 final-verification.json 및 captures/*-final-*.json에 있습니다. build-state.json의 source SHA256과 캡처의 SHA256을 일치시켜 오래된 빌드가 제출되지 않도록 확인했습니다.

## 라이브러리 별도 검사

첨부 preview.py로 light.html과 dark.html을 생성했습니다. 31개 요소의 범위 선택자·토큰·타입 단계·메타데이터·fixture를 정적으로 검사했습니다. 최소 크기는 예시 컬렉션의 주석을 그대로 신뢰하지 않고 실제 구현으로 수정했습니다.

라이트·다크에서 선언된 최소칸부터 12×6까지 모든 정수 열·행 조합을 검사했습니다. 총 **3,610개 크기 조합, 지적 0건**입니다. 텍스트의 슬롯 초과, 상자 초과, 실제 줄별 겹침, 숫자 중간 줄바꿈을 검사했으며 스냅샷 HTML의 SHA256과 현재 HTML의 일치도 확인했습니다. 기록은 library-min-check.json입니다.

수정한 항목은 태그의 크기 수축, 카드의 root tone 선택자, 중첩 요소의 size containment, 요금제의 글자 크기 선택자 우선순위, 순환·허브 연결선, 선 차트의 이중 padding 감산, 가로 막대 숫자 줄바꿈, 퍼널의 좁은 단계와 긴 라벨입니다. 다크 tone-3 글자 대비는 짙은 전경색으로 보정했습니다.

## 해석과 어려웠던 요소

- 사진·인물·제품·복잡한 이미지와 기기 화면은 요청대로 #e5e5e5 단색 placeholder입니다. 사진이 큰 비중을 차지하는 098·106의 시각 차이는 이 처리에서 주로 발생합니다.
- 원본에 폰트 파일이나 이름 정보가 없어 Pretendard Variable, Noto Sans KR 300–900, Inter Variable 중 형태와 폭이 가까운 조합을 실제 로드했습니다. 동일한 원본 폰트임을 확인한 것은 아닙니다.
- 작은 보조 문구는 읽히는 범위에서 전사했고, 판독할 수 없는 곳은 자연스러운 비즈니스 문장으로 작성했습니다. 작은 글자를 선이나 가짜 무늬로 대체하지 않았습니다.
- 104의 세로줄 원형 배경·광택, 101의 면적 차트, 105의 기기 외곽, 106의 제품/스마트폰 배치가 까다로웠습니다. 사진을 제외한 도형과 선·그래프는 SVG/HTML로 구현했습니다.
- Lucide로 치환한 아이콘, 벡터로 그린 브랜드 심볼·서명, 일부 부분색 강조와 미세한 광택에는 자형·안티앨리어싱·세부색 차이가 남습니다. 원본과의 픽셀 완전 일치를 주장하지 않습니다.
- 참고에 없는 순환·계층·요금제 등은 가는 선, 낮은 모서리 반경, 파랑 정보 위계, 민트·코랄 보조색, 넓은 여백으로 같은 언어를 확장했습니다.
- 카드·표·다중 요금제의 최소칸은 가독성을 위해 보수적으로 정했습니다. 소형 칸에서 이름이나 수치를 숨겨 통과시키지 않았습니다.

## 산출물 안내

전체 결과 ZIP에는 원본 재현 76 PNG, 라이브러리 재조립 76 PNG, 원본/결과 비교 76 JPG, 라이브러리 178 PNG, 전체 미리보기 HTML, 덱별·전체 PDF, 1280×720 연락처 시트 PNG/PDF, 검수 기록, 컬렉션 ZIP, 소스 ZIP이 있습니다. PDF의 슬라이드 크기는 16:9이며 브라우저로 출력해 텍스트와 벡터를 유지했습니다. 연락처 시트 PDF는 시트 이미지로 구성했습니다.

로컬 ZIP 무결성과 이미지 크기를 확인한 후 GitHub에 일반 push합니다. 이후 GitHub에서 ZIP을 다시 다운로드해 SHA256 및 CRC를 확인한 결과는 github-download-verification.json에 별도로 기록합니다.

통합 검사에서는 가려진 메타데이터 중복과 의도적인 부분색 텍스트 겹침도 정리했습니다. 부분색 문장은 하나의 rich-text 노드로 바꿨고, 수치 단위 사이 간격을 조정했습니다. 선의 음수 방향 좌표 정규화와 도넛의 글자 스타일을 조립기에 반영했습니다. 폰트는 화면에 사용된 실제 문자열을 굵기·크기·서체별로 명시적으로 로드한 뒤 광학 중심과 최종 스크린샷을 계산합니다.
