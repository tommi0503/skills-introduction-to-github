# Onboard Docket 검수 기록

## 범위와 순서

078 덱의 slide_01–19, 19장 전부를 읽고 replica HTML을 먼저 작성했다. 이후 디자인 언어를 문서화하고 foundation과 56개 요소를 제작했으며, 마지막에 계약 마크업만으로 19장을 다시 조립했다. 다른 샘플의 디자인 CSS는 읽거나 가져오지 않았다. fixture는 지정 모범 구성의 마크업·데이터와 비지정 계약 구조 예시를 사용했고 data-el만 이 컬렉션으로 바꿨다.

## 실제 비교와 수정

- 원본 19장 각각을 전체 크기로 확인했다. 실제 Chromium 브라우저에서 replica를 렌더하고 19개의 원본 | replica 쌍을 한 장씩 보았다. 연락처 시트만으로 검수를 끝내지 않았다.
- 비교 뒤 표지 라틴 제목의 폭, CHAPTER 제목의 세로 위치, 인재상 도넛 시작 각도, 세로 단계 탭의 직각 모서리, 키워드 반원 도형의 종이 끝 잘림을 수정했다.
- 폰트 요청이 실패한 404 초기 환경 렌더는 검수 결과에서 제외했다. HTTP 200 응답과 실제 font load를 확인하는 경로로 고쳤다.
- 라이트·다크 시트에서 제목 정렬, 작은 칸의 글자와 긴 가로 차트 라벨, 단위 색, 강조 면의 대비를 검토했다. 카드 제목은 내용 길이에 관계없이 같은 트랙에서 시작하도록 고쳤다.
- 선 차트는 앞 점과 현재 점을 잇는 실제 CSS anchor 선으로, 영역 차트는 현재 값과 앞 점 위치로 계산한 보간 다각형으로 수정했다. 특정 fixture 값에 맞춘 하드코딩은 사용하지 않았다. 공유한 것은 이 좌표 계산 방법뿐이며 디자인 CSS는 독립적이다.
- 조립본 19개 비교 쌍을 각 장별로 보았다. 표지 제목 위치, 한 줄 pill 높이, 작은 카드 note 보존, 단계 제목 정렬, 원본의 반원형 hub 문법을 요소 CSS에 반영했다. 브라우저 기본 body 8px 여백도 중립 출력 프레임에서 제거했다.

## 판독 불가·추정과 계약 충돌

본문은 대체로 판독 가능했다. 로고의 원본 벡터 형태와 사진 내부의 아주 작은 화면 문구는 전사하지 않고 자리로 처리했다. 서명 김미리는 읽을 수 있지만 정확한 원본 서명 글꼴은 미확인이다. 원본의 긴 안내문은 조립본에서도 유지했다. 작은 로고의 고유 도형과 사진에 붙은 안내는 이미지 자리로 처리했고, 본문 판독 불가를 이유로 새 핵심 문장을 만들지는 않았다.

지정 모범 fixture card-4에는 원본 샘플부터 `✹` 아이콘 문자가 들어 있다. "같은 마크업과 데이터"라는 사용자 지정 요구를 지키기 위해 이 한 곳은 그대로 보존했다. 새 fixture나 조립본에 새 문자 아이콘을 만들지는 않았다.

## 자동 검수의 해석

렌더 크기·font load·요청 실패·문자 범위·부모 잘림·칩 중심·대비는 루트 통합 검수의 JSON 결과와 최종 렌더 지문을 함께 제출한다. 문자 잉크의 자연스러운 line-box 초과와 실제 조상 overflow 잘림을 구분했다. 마지막 소스 변경 뒤 최종 렌더가 다시 수행되어야 하며, 최종 PNG/PDF 생성과 ZIP 무결성·다운로드 검증은 주 에이전트의 통합 단계에서 확인한다. 이 문서는 통과하지 않은 항목을 자동 통과로 주장하지 않는다.


## 최종 통합 검수의 계약 해석

- 필수 모범 fixture는 data-el의 컬렉션 접두사만 바꾸고 마크업·데이터·배치 값을 보존했다. 이 때문에 card-4의 원문 문자 아이콘과 callout-stack의 농업 문구는 일반 아이콘·비즈니스 문장 규칙의 예외로 남겼다. 새 아이콘은 빈 data-icon 방식만 사용했다.
- 모범 fixture 외의 최상위 배치는 12×6으로 정규화했다. 일반 prose-pair/prose-quiet의 농업 문구는 한국어 비즈니스 문장으로 교체했다. 일반 bullet fixture의 --v:104와104%는 계약 범위0–100을 지키도록96과96%로 함께 수정했다.
- 요소 시트는 제공된 기준 팔레트로 검수했다. 재조립은 원본 색을 공급하는 외부 source-palette, type-steps, JSON tokenDefaults 공급 파일을 사용한다. 이 파일은 페이지별 디자인 CSS를 추가하지 않는다.
- 독립 HTML의 기본 여백을0으로 맞추고, 로컬 글꼴과 Lucide 런타임을 넣었다. 이는 Rhetis가 제공하는 렌더 환경을 재현하는 공급부이며, 컬렉션 ZIP에는 CSS·JSON·MD·HTML만 있다.
- 페이지 PNG는1280×720, 원본과의 좌우 비교 PNG는2560×720이다. 요소 시트는 fixture 수에 따라 높이가 달라 실제 크기를 build-verification.json에 기록했다.
- 원시 overflow 후보에는 글꼴의 잉크가 line box를5–7px 넘지만 overflow:visible로 읽히는 경우가 포함된다. 별도 검수에서는 실제 잘리는 조상 영역과 주어진 칸의 범위를 확인했다.
- 제공된 팩에는 Rhetis 반입 엔진이 없어 upstream intake는 실행하지 않았다. 제공 preview CLI, 독립 정적 계약 검사, 실제 Chromium 출력과 ZIP 검사를 사용했다.

### 초기 통합 단계의 요소별 기능 검수(구조 복원 이전)

56개 요소의 라이트·다크 개별 시트와 실제 Lucide가 수화된 조립본 19장을 확인했다. 도넛의 원형 경계와 0/100%, 수평 선분, 기본 누적 계열의 색 구분, balance의 기울기 부호, bullet의 목표 위치, journey의 점 연결을 보정했다. mindmap·hierarchy의 연결선을 노드까지 이어지게 하고, Sankey의 원천 면을 전체 높이의 세로 띠로 만들어 모든 분기가 원천과 접하게 했다. 짧은 카드의 제목/설명을 세로로 배치해 한 글자씩 줄바꿈되는 문제를 없앴다.

최소 칸에서 100칸 waffle, 짧은 인물 waffle, 프로필 사진, Venn 원의 경계와 이름, pyramid 꼭짓점 설명을 다시 검사했다. pyramid의 삼각형은 배경 pseudo-element에만 잘림을 적용해 글자가 사라지지 않게 했다. 짧은 인물 waffle은 아이콘·수치·이름을 한 행에 놓고 부가 small 메모만 숨긴다. 공식 preview의 빈 data-icon 점선 원은 계약대로 유지하며 실제 조립 페이지는 Lucide를 표시한다.

영향 요소 25종의 라이트·다크 시트를 별도 브라우저로 재생성했으며 최소 칸 조상 overflow로 잘린 텍스트는 0건이었다. 독립 데이터 프로브에서 새 값 37의 연속 수평 선분 높이는 양쪽 모두 2px, untoned 3계열의 배경색은 서로 달랐다. 인물/waffle/Venn 최소 칸 도형 경계 검사도 라이트·다크 모두 초과 0건이었다. 최종 전체 PNG/PDF는 통합 렌더러가 동결된 CSS로 다시 생성한다.


## 최종 복원 검수와 예외

상세 구조 복원 뒤 19개의 원본|조립본 비교를 다시 개별 확인했다. 초기 전반 검수와 구조 복원 검수, 마지막 회귀 검수를 구별하고, 부분적인 폰트·줄바꿈 보정은 대상 장을 다시 렌더했다. 최종 비교 PNG는 qa-fidelity-targets에 기록했으며 납품 비교 폴더·PDF는 통합 렌더러가 최신 소스로 재생성한다.
