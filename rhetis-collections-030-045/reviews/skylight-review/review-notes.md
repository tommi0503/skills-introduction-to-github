# Skylight 검수 기록

## 범위와 제작 순서

038 업무환경 개선안 21장 전부가 대상이다. `inventory.md`에 이미지별 유형과 요소 계약을 정리했다. 계약 README 전체를 읽고 목록 → 21장 replica → 브라우저에서 원본과 개별 비교 → 디자인 언어 → 56종 요소 → 라이트·다크 라이브러리 → 21장 재조립으로 진행했다. 최종 비교 PNG 42개도 한 장씩 열어 확인했다. 원본 통이미지를 배경으로 쓰지 않았다.

비교와 수정은 초기 재현, 타이포·도형 수정, 조립 동일성 복원이라는 세 묶음으로 정리했다. 초기 조립본 17장의 구조를 단순화한 판단은 잘못이었다. 최종본은 replica의 좌표를 기준으로 왼쪽 세 행 레이블, Q1부터 다음해 상반기까지의 시기 행, 다섯 본문 카드, 점검 사항 행을 복구했다. 다른 페이지의 큰 패널·전후 비교·화살표·사진 자리도 다시 대조했다. 통합 검토의 구체 결함은 마지막 묶음에 포함했다.

## 폰트·사진·판독과 색의 결정

- 원본 폰트 이름이 없어 동일 서체라고 확정할 수 없다. 제공 표의 Noto Sans KR를 제목·표지에, Pretendard Variable을 본문·수치에 실제 로드했다. 키트의 두 공유 font 토큰을 사용한다. 원본과 글자 폭·세부 굵기·일부 줄바꿈 차이가 남는다.
- 사진·인물·실내 이미지는 요청대로 연회색 단색 자리로 치환했다. 조립본의 자리도 추가 번호 없이 비웠고, 라이브러리 fixture의 계약 번호는 보존했다. 단순 도형과 배경은 CSS gradient·clip-path·SVG로 구현했다.
- 원본의 “입력해 보세요”, “XX%”, “X억원” 등의 문구는 자료로 보존했다. 작업 지시로 실행하지 않았다. 읽힌 설명의 일부 띄어쓰기와 구두점을 정리했다. 판독 불가 문구를 선으로 대체한 곳은 없다. 비모범 fixture의 영문 placeholder는 “서비스 기획” 등 한국어 업무 문구로 바꿨다.
- 컬렉션 CSS는 원본 파랑을 고정하지 않는다. 합법 palette 자리만 사용하고, 조립 미리보기 host palette에서 원본의 색을 근접하게 주입했다. 기본 라이브러리 시트의 주황·갈색은 reference palette의 결과다.
- 17장 회색 레이블은 원본처럼 흰 글자를 쓰되 컬렉션의 면은 더 진한 n-7로 옮겨 대비를 확보했다. replica는 원본의 옅은 회색을 유지한다. 작은 accent 제목도 대비를 위해 진한 역할색을 썼다.

## 라이브러리 계약과 브라우저 검수

요소 56종, 요소 fixture 175개, foundation fixture 2개다. 시트와 PDF는 모드당 177페이지다. README 모범 구성 28개는 data-el prefix 외에 마크업·데이터가 동일함을 문자열 비교했다. 나머지는 2개 이상 fixture와 긴 문장·멤버 수·변형을 포함한다. 추가 일정표·문화 전후 표·다분할 donut 합성·축 표시 fixture도 실제 CSS로 렌더했다.

예시 컬렉션의 디자인 CSS는 복제하지 않았다. 원본의 직사각 면, 진한 상단 띠, 작은 직각 라벨, 점선 구분, 결론 capsule과 모서리 접힘을 추출했다. 모든 요소 선택자는 자기 data-el에 묶이고 font-size는 직접 type 토큰을 사용한다. 여백·굵기·행간·반경 등은 공유 토큰을 사용한다. 차트 축 단계, donut 시작각·hole, venn 겹침은 명시적 등록 토큰이다.

최소 격자부터 12×6까지 가능한 정수 크기를 두 모드에서 검사했다. 최종 횟수와 실제 findings는 `automatic-checks.json`에 기록한다. 42개 페이지의 실제 text range, 페이지 크기, 폰트 로딩과 칩·태그 72개의 문자/박스 중심도 측정했다. 추가로 source05의 120px 키워드 pill 3개는 root/parts padding 중복을 풀어 x오차 0.00px, y오차 약 -0.30px로 보정했다. 전체 파일의 해시를 함께 남겼다.

gauge의 긴 이름은 keep-all로 단어 단위 줄바꿈해 마지막 한 글자만 남는 현상을 고쳤다.

수정한 문제는 내포 list의 높이 0, 면 차트 baseline의 톱니, radar의 가로 늘어짐과 범례 겹침, 작은 code/steps/list/흐름도 잘림, 밝은 강조색 위 작은 글자 대비였다. radar는 가용 폭과 높이의 작은 값을 사용한 정사각형이고 범례는 위쪽 독립 영역이다. 선·면 차트는 CSS anchor로 인접 점을 연결한다.

preview.py의 전역 `.frame`와 `small`이 계약 요소로 누출되던 문제는 생성 시트의 wrapper 선택자만 좁혀 고쳤다. 헤더 없는 요소 fixture는 실제 가용 body 높이를 쓰며, 헤더 있는 원본 조립 페이지의 본문 시작 위치를 억지로 적용하지 않는다. foundation의 lead/title/kicker도 head와 lockup의 직계 자식으로 한정했다.

## 산출물 확인과 한계

페이지 PNG 42개는 모두 1280×720, 비교 PNG 42개는 모두 2560×720이다. 라이브러리 PNG는 foundation 포함 57개 폴더에 라이트·다크 114개이며 모든 fixture를 담는다. 라이브러리 시트 폭은 1280이고 높이는 fixture 수에 따른다. replica/reassembled PDF는 각 21페이지, library PDF는 각 177페이지다. 최종 수정 후 HTML을 다시 렌더하고 그 PNG로 비교와 PDF를 갱신했다.

브라우저의 text range·중심·대비 후보 검사는 시각 검토를 보조한다. 모든 글자의 픽셀 동일성이나 내부 반입 성공을 보장하지 않는다. reference pack에는 Rhetis 내부 importer가 없다. ZIP 구조·무결성·저장소 push·게시 ZIP 재다운로드 검증은 전체 6개 통합 단계에서 주 에이전트가 수행한다.

최종 픽셀 대비 재검수: table 일정표 중간 좌레일의 gradient 끝을 a1-5-soft 50%와 a1 혼합으로 보정했다. 실제 글자를 투명하게 숨긴 배경 PNG에서 샘플한 dark 대비는 ‘추진’4.79:1, ‘일정’4.80:1로 4.5:1을 넘는다. 첫 회색 레일은 7.41:1이고 gauge 4건은 4.55–6.25:1이다. replica와 큰 배치는 유지했으며 해당 시트·17장·PDF를 다시 렌더했다.

조립04의 semantic foundation recipe는 body 시작을 3px 위로 옮기고 split 음수 margin을 0으로 바꿨다. body와 split은 모두 x66/y210/1148×390으로 일치하며 실제 그림 위치는 바뀌지 않았다. HTML과 CSS bundle만 갱신했고 PNG는 동일하다.


## 주 에이전트 최종 통합 검수

초기 재조립의 큰 배치 차이를 그리드 제약으로 남긴 판단을 철회하고, 원본과 각 페이지를 개별 비교해 원본 비율·위계·연결선·표 구조로 수정했다. 최종 비교 PNG의 SHA-256을 시각 검수 기록에 묶어, 검수 뒤 파일이 바뀌지 않았는지 확인했다. 폰트 정보가 없는 원본은 실제 로드한 제공 글꼴로 맞췄으며, 남는 글자 윤곽·작은 아이콘·대비 보정의 차이는 위 기록을 따른다.

최종 소스의 180개 페이지를 브라우저로 다시 렌더해 저장 PNG와 픽셀 단위 일치를 확인했고, 모든 페이지의 1280×720·폰트 로드·텍스트 경계·요소 박스·텍스트 캡슐의 실제 글리프 중심을 검사했다. 라이브러리는 라이트/다크 최소·중간·12×6 검사와 CSS 범위/계약 검사를 수행했다. 가상요소·그라디언트로 인한 대비 후보는 실제 화면을 확인해 별도 기록했다.

모범 card-4의 원문 ✹와 모범 callout의 배치는 같은 마크업·데이터 보존 요구를 우선했다. 다른 아이콘은 빈 Lucide slot이며, 다른 fixture의 최상위 배치는 12×6이다. 페이지 PDF는 마지막 PNG로 무손실 조립하고 PDF를 다시 래스터화해 같은 픽셀인지 확인했다. 라이브러리 PDF는 최종 fixture 전체를 포함한다.

`lead-integration.json`은 독립 최종 검사와 대비 판정, `lead-final-files.json`은 최종 파일 크기·SHA-256의 기준이다.
