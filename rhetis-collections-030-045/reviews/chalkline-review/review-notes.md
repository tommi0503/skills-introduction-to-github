# Chalkline 검수 기록

## 작업 순서와 근거

1. reference README 220줄을 끝까지 읽고 030 덱의 원본 2장(모두 1280×720)을 개별 확인했습니다. `inventory.md`에 페이지 유형과 관찰된 계약을 연결했습니다.
2. 원본 전체 이미지를 사용하지 않고 HTML 텍스트·배치·표·간단한 SVG 기호로 replica 2장을 작성했습니다. 실제 Chromium에서 Pretendard Variable을 로드하고, 페이지별 원본 | replica PNG를 열어 각각 비교했습니다.
3. 그 후 디자인 언어를 문서화하고 키트·foundation·56개 요소·171개 요소 fixture를 제작했습니다. 지정된 card/callout/area/bar/donut/line 모범 fixture는 내용과 구조를 유지하며 컬렉션 data-el로 옮겼습니다. 비모범 fixture도 2개 이상이며 멤버 수·긴 내용·변형을 포함합니다.
4. 제공된 preview.py로 light/dark HTML을 생성했습니다. 각 fixture를 실제 브라우저의 1280×720 슬라이드로 렌더하고 요소별 시트와 전체 PDF를 생성했습니다. 실제 slot 크기를 최소 주석값·중간값·12×6으로 바꿔 513 case씩 두 모드에서 텍스트·대비를 검사했습니다.
5. collection CSS만으로 원본 2장을 재조립했습니다. reassembled HTML에는 호스트가 공급하는 팔레트·type-N·폰트 및 출력용 1280×720 wrapper만 추가하며, 페이지별 디자인 CSS는 없습니다. 원본 | 조립본 PNG를 각각 검토했습니다.

## 비교와 수정

- 비교·수정은 초회 검토, 공통 원인 수정, 최종 보정의 세 묶음으로 진행했습니다.
- replica 초회에서 바탕의 차이를 픽셀로 확인하여 `#f6f6f6`으로 맞췄습니다. 비교행·FAQ의 원본 줄바꿈을 명시적으로 보존했습니다.
- library에서는 중첩 list의 size containment로 높이와 너비가 0에 가깝게 계산되는 문제를 고쳤습니다. 실제 배치 슬롯만 size containment를 가지며 중첩 내용은 자연 높이를 유지합니다.
- donut과 concentric의 폭·높이가 따로 제한되어 생기던 타원 변형을 고쳤습니다. 좁은 treemap 타일의 이름과 값을 세로로 배열했습니다. radar는 폴리곤 채움만 clip하며 범례는 독립된 상단 영역에 둡니다.
- pricing/person/pill의 중첩 리스트 높이, 작은 가로 막대의 긴 라벨, 작은 누적 막대의 수치 충돌, slope의 가까운 값 표기를 수정했습니다. 극소 누적값은 막대 위/아래로 번갈아 표시합니다.
- 브라우저 기준 style에서 작은 `--a1` 텍스트의 대비가 낮아 강조 이름은 깊은 `--a1-7`을 사용했습니다. preview wrapper의 전역 small 스타일 누출은 scoped `small { color:inherit }`로 막았습니다.
- preview.py의 전역 `.frame` wrapper 규칙은 계약의 image-frame `.frame`에도 적용되는 충돌이 있어, 생성 HTML에서 wrapper만 `article > .frame`으로 좁혔습니다. 컬렉션 CSS를 바꾸어 외부 wrapper 문제를 숨기지 않았습니다.
- 최상위 fixture의 12×6 nominal placement를 정규화하고 실제 minimum은 주석으로 선언했습니다. 모범 fixture의 구체적인 원본 placement는 동일 markup/data 요구에 따라 보존합니다.
- collection에는 CSS/JSON/MD/HTML만 있습니다. 폰트는 review에만 넣었습니다. code 요소는 제공된 Nanum Gothic Coding을 전용 키트 font 토큰으로 실제 로드합니다.

## 남는 차이와 해석

- 원본 폰트 메타데이터가 없으므로 원본과 동일한 폰트라고 단정할 수 없습니다. 제공 글꼴 중 형태가 가까운 Pretendard Variable을 선택했습니다. 400/500/700/750 굵기와 텍스트 줄바꿈을 직접 맞췄습니다.
- 단순 로고 마크는 SVG 직선·원으로 재현했으며, foundation에서는 둥근 대각선 두 획과 원을 CSS 기하로 구현했습니다. 원본의 곡률과 픽셀 가장자리는 완전히 같지는 않습니다.
- 원본 2장에 사진·3D·기기 화면이 없어 replica에는 회색 대체 사진이 필요하지 않았습니다. library의 미관찰 media/person 요소에는 계약의 번호가 가운데 있는 회색 seat를 사용합니다.
- 원본의 모든 본문은 판독 가능하여 원본 페이지에 임의로 지어 넣은 문장은 없습니다. library의 미관찰 요소에 쓰인 실제 같은 한국어 문장·수치는 fixture 데이터이며 원본에서 읽은 정보로 주장하지 않습니다.
- 최종 통합 검수에서 그리드 양자화 차이를 허용하지 않고 foundation 12×6의 트랙 비율을 실측 복구했습니다. body는 원본처럼 x297/y153/916×522이며, row3은 y313, row5는 y489입니다. FAQ는 quiet 카드의 내부 리듬으로 y322/498(원본 제목 글자의 시각적 위치에 맞춘 2px 보정), 좌우 열 너비는 원본의428/448px입니다. 비교표는 y313에서 높이340px로 끝나도록 고쳤습니다. 큰 제목은48px/1.32, 원본 줄바꿈은 markup의 br로 유지합니다. 페이지별 새 CSS는 없습니다. 원본 폰트 파일은 확인할 수 없어 가까운 Pretendard를 실제 로드했으며 글자 윤곽·획의 차이는 남습니다.
- 원본은 무채색이지만 library 시트의 강조색은 README 기준 palette가 공급합니다. palette의 색이 바뀌어도 얇은 선·직각 면·좌측 레일·작은 원형 마크·알약 분류라는 형태는 유지합니다.
- 030은 본래 덱의 14–15번 두 페이지만 들어 있는 조각입니다. 표지와 원본에 없는 56종의 대부분은 관찰한 규칙을 확장한 설계입니다. 큰 그림자·둥근 카드 테두리·의미 없는 장식은 추가하지 않았습니다.

## 자동 검사

- 실제 Chromium, document.fonts.ready 이후 렌더. 페이지 4개(2 replica + 2 reassembled) 모두 1280×720, 폰트 로드 성공, 페이지 밖 DOM 영역 없음.
- library 171개 요소 fixture + foundation 2개, 라이트·다크 각각 173개 렌더. 요소 폴더마다 전체 fixture를 담은 시트 1장씩 두 모드입니다.
- 최소·중간·12×6: 513 case × 2모드. 최종 overflow/overlap 후보 0, 대비 후보 0. 원형/알약의 실제 glyph bounds 중심도 별도 검사하며 결과는 automatic-checks.json에 기록합니다.
- 마지막 수정 이후 페이지 PNG, 요소 시트, PDF를 다시 생성하고 SHA-256와 생성 시각을 기록했습니다. zip과 원격 다운로드 검증은 통합 주 에이전트가 수행합니다.
- 검사기는 텍스트 range 및 DOM 경계 기반입니다. Rhetis intake 자체는 이 reference pack에 포함되지 않아 실제 intake를 실행했다고 주장하지 않습니다.

## 최종 도형·시각 중심 확인

요소별 시트를 라이트·다크 모두 56종씩 개별 열람했습니다. 텍스트 검사만으로 잡히지 않는 도형의 의미도 확인했습니다. slope는 각 쌍의 실제 --a/--b로 선의 양 끝을 계산하고, radar는 원형 가이드·방사축·실제 폴리곤만 남겼습니다. cycle은 다음 노드로 이어지는 완전한 루프, hub는 중심으로 모이는 방사선, mindmap은 중앙 캡슐에 닿는 곡선 연결로 정리했습니다. flowchart/swimlane은 한 노드에 방향이 여러 개 있어도 각각의 화살표가 실제 다음 칸까지 이어집니다. 여러 시리즈가 있는 누적 막대는 주 강조 하나와 구분되는 중립 단계를 사용합니다.

칩의 전체 parts 박스만 가운데에 있는 것으로 끝내지 않았습니다. 숫자 mark의 불필요한 고정 폭을 제거한 뒤, 테두리와 분리된 실제 glyph 픽셀 bounds의 중심을 검사했습니다. 최종 176개 캡슐/배지에서 좌우·상하 4px 기준을 모두 통과했습니다. 자동 추출 과정에서 테두리의 안티앨리어싱이 글자로 잡히는 후보는 inset 경계에 닿는 연결 성분을 제외하는 방식으로 구분했습니다. 결과와 측정 방법은 chip-alignment.json에 있습니다.

## 실측 복원 최종 보정

비교표의 굵은 제목/보통 본문을 구분하고, FAQ를 원본428/448px 비대칭과176px 세로 리듬으로 복구했습니다. 상단 선도 본문보다7px 안쪽으로 들어가도록 맞췄습니다. 비균등 트랙에서 실제로 견디는 최소 칸은 chart-stack12·hierarchy3·세로 timeline4가5행, roadmap4가10열·5행으로 다시 선언하고 브라우저에서 검증했습니다. 이 변경은 실제 가독 공간을 정직하게 선언하기 위한 결정입니다.


## 주 에이전트 최종 통합 검수

초기 재조립의 큰 배치 차이를 그리드 제약으로 남긴 판단을 철회하고, 원본과 각 페이지를 개별 비교해 원본 비율·위계·연결선·표 구조로 수정했다. 최종 비교 PNG의 SHA-256을 시각 검수 기록에 묶어, 검수 뒤 파일이 바뀌지 않았는지 확인했다. 폰트 정보가 없는 원본은 실제 로드한 제공 글꼴로 맞췄으며, 남는 글자 윤곽·작은 아이콘·대비 보정의 차이는 위 기록을 따른다.

최종 소스의 180개 페이지를 브라우저로 다시 렌더해 저장 PNG와 픽셀 단위 일치를 확인했고, 모든 페이지의 1280×720·폰트 로드·텍스트 경계·요소 박스·텍스트 캡슐의 실제 글리프 중심을 검사했다. 라이브러리는 라이트/다크 최소·중간·12×6 검사와 CSS 범위/계약 검사를 수행했다. 가상요소·그라디언트로 인한 대비 후보는 실제 화면을 확인해 별도 기록했다.

모범 card-4의 원문 ✹와 모범 callout의 배치는 같은 마크업·데이터 보존 요구를 우선했다. 다른 아이콘은 빈 Lucide slot이며, 다른 fixture의 최상위 배치는 12×6이다. 페이지 PDF는 마지막 PNG로 무손실 조립하고 PDF를 다시 래스터화해 같은 픽셀인지 확인했다. 라이브러리 PDF는 최종 fixture 전체를 포함한다.

`lead-integration.json`은 독립 최종 검사와 대비 판정, `lead-final-files.json`은 최종 파일 크기·SHA-256의 기준이다.
