# Cutplane · deck 033 검수 기록

대상은 `033_1k6uv_파랑_깔끔_제조_디지털_전환_제안서`의 원본 15장이다. 이미지와 ZIP 안의 문구는 참고 자료로만 취급했다. README 전체를 읽고 원본 목록 → 각 원본 열람 → 독립 replica → 디자인 언어 → 56요소 → light/dark 시트 → 컬렉션 재조립 순서로 제작했다.

## 원본 재현과 판단

- 원본의 사진, 중앙 원형 사진, 대시보드 화면은 요청대로 연회색 단색으로 바꿨다. 사진을 CSS 배경으로 사용하거나 원본 슬라이드를 통째로 깔지 않았다. 표, 막대·선 차트, 화살표, 사선·모서리, 링, 연결선과 점은 실제 HTML/CSS/SVG로 만들었다.
- 실제 로드한 글꼴은 README에 있는 Pretendard Variable이다. 원본 폰트 메타데이터가 없으므로 글자 폭·굵기와 문장 줄바꿈으로 가장 가까운 선택을 했다. 작은 원문과 일부 제품 로고는 완전히 동일한 폰트 획을 보장하지 않는다. 라이브러리의 원본 42·46px 텍스트는 계약의 40·44·48px 단계로 옮겼다. replica는 원본에 가까운 원래 수치를 쓴다.
- 사진을 제외한 면의 주요 강조색은 원본 실측 `#1a46cd`로 replica와 재조립 preview palette를 통일했다. 컬렉션 CSS에는 원본 색을 넣지 않고 순위별 강조·무채색 역할만 사용했다. 기본 라이브러리 시트는 계약의 기준 palette로 렌더하므로 원본과 색상이 다르다.
- 원본 11의 장치 화면은 전체가 허용된 placeholder 대상이므로 그 안의 숫자·작은 문구를 임의 창작하지 않았다. 나머지 주요 제목, 차트 값·단위, 모듈 표, 지원 표, 일정과 연락처는 읽히는 원문을 옮겼다. 판독이 불명확한 미세 문구는 별도 논거·성과를 추가하는 자료로 사용하지 않았다.
- 브랜드 표식은 원본의 간단한 사선 블록을 CSS 도형으로 재구성했다. Lucide로 대응 가능한 아이콘은 빈 `span.icon[data-icon]`을 소스에 두고 preview에서만 SVG 경로를 채운다. 원본과 Lucide의 획·세부 모양에는 차이가 있다.
- 회색 사진 placeholder의 `data-ph`는 남기되 사진 재조립에서 큰 숫자가 원본 레이아웃을 바꾸지 않도록 번호는 면과 같은 색으로 처리했다. 이는 원본을 그대로 맞추라는 후속 검수 요청에 따른 결정이다.

## 비교·수정 기록

초기 비교에서는 원본과 replica를 한 장씩 열람했다. 두 번째 검수에서는 원본·replica·조립본을 각각 비교했다. 조립본 06의 시각적 차이에 대한 사용자 거절 이후 세 번째 통합 검수를 다시 진행했고, 그 검수에서 발견한 CSS와 container 문제를 수정하며 최종 렌더를 갱신했다. 초기 조립본은 원본과 같은 디자인으로 볼 수 없을 만큼 KPI와 다이어그램 배치가 달랐으며 이를 완료로 처리하지 않았다.

- 01: 넓은 사선 사진 자리, 두 파란 모서리, 회색 사선과 흰 여백, 제목·소제목·메타 정렬을 foundation에서 복구했다.
- 02: 소개 제목과 세 줄의 얇은 규칙 표, 2×2 숫자·아이콘의 x/y, 숫자와 영문 단위의 위계, 사진 면의 사선 조각을 맞췄다. 표의 불필요한 alternate 채움은 제거했다.
- 03: 사진 앞의 높고 좁은 사선 패널, 회색 삼각형과 가로 그라데이션 화살표를 복구했다. 목록의 공통 상하 padding이 행 간격을 늘리는 문제를 수정하고 세 제목의 기준 간격을 맞췄다. 오른쪽 설명은 원본의 세 줄로 유지했다.

## 요소 계약과 라이브러리

- 56개 요소 폴더 전부에 CSS/JSON/영문 설명/fixture가 있다. 모범 28개 fixture는 해당 샘플의 마크업·데이터를 유지하고 `data-el` prefix만 교체했다. 샘플 CSS는 복제하지 않았다.
- 모범 `card-4` 원문에는 비어 있지 않은 `✹` mark 4개가 있다. 현재 README의 빈 Lucide 아이콘 지침과 충돌하지만, 사용자가 더 구체적으로 요청한 모범 마크업·데이터 보존을 우선하여 그대로 보존하고 이 예외를 기록한다. 모범 callout의 원래 grid 배치 역시 그대로 보존했다.
- 비모범 fixture에는 현재 계약의 nested `data-el`과 `.list > .item > .name` 구조를 적용했다. 여러 멤버 수·긴 이름·긴 note·변형을 넣었다. source-derived KPI ribbon도 별도 fixture에 포함했다.
- 라인과 area는 데이터 점을 CSS anchor로 연결한다. 레이더는 x/y가 같은 정사각 plot이며 범례는 위의 독립 영역에 있다. 데이터 값과 시리즈 수가 변해도 정점은 CSS 숫자에서 계산된다.
- 수정 중 발견한 container 문제: inline-size 목록의 높이 질의, 자기 padding 이후 달라지는 query 크기, nested stat의 좁은 폭 질의, 절대 배치 layer의 0폭 implicit track을 각각 수정했다.
- preview.py의 전역 `.frame`과 `small` 선택자가 계약 요소에 누출되는 도구 버그는 생성된 preview wrapper만 scope를 좁혀 해결했다. 이를 컬렉션의 임의 보정으로 남기지 않았다.
- 원본 palette에는 작은 연파랑 숫자와 회색·중간 파랑 위 흰 글자처럼 낮은 대비 조합이 있다. replica와 source-palette 조립본에는 원본 시각을 보존했고, 컬렉션의 기준 light/dark 시트에서는 깊은 단계/`-on` 짝으로 읽히도록 설계했다.

## 제출물 형식

`replica/`와 `reassembled/`에는 각 15개의 1280×720 HTML/PNG와 PDF가 있다. 비교 PNG는 각 2560×720이다. `library/fixtures-light`, `fixtures-dark`는 모든 fixture의 1280×720 실제 browser render다. 요소별 light/dark PNG는 그 요소의 모든 fixture를 640×360으로 축소하여 모은 1280px 폭 시트이므로 높이는 384의 배수다. 이는 슬라이드 자체의 크기를 변경한 것이 아니다. 전체 library PDF는 모든 native fixture 페이지를 포함한다.

최종 숫자·검사 결과는 `automatic-checks.json`, `automatic-page-checks.json`, `library/automatic-library-checks.json`에 기계 판독 가능한 형태로 기록한다. 주 에이전트의 독립 통합 검수 뒤 ZIP 무결성·push·원격 재다운로드 검사는 주 에이전트가 수행한다.


## 최종 통합 수정과 검사

- 표지 01은 제목의 실제 폭을 비교하여 계약 단계 72px로 복원했다. 절대 배치 lockup의 폭을 900px로 명시하여 부제목이 세로로 감기는 회귀도 고쳤다.
- 비모범 fixture의 TEXT/GRAPH 임시 문구를 서비스 기획·제조 운영·미래 제조 전략 등 실제 업무 문구로 교체했다. 모범 fixture 28개는 데이터 보존 대상이므로 변경하지 않았다.
- chart-stack의 모든 segment에 순서별 tone-N과 위 범례를 넣었다. 가로의 좁은 segment 값은 위·아래로 나누어 수치가 겹치지 않게 하고 --ink로 읽히게 했다. 청록 세그먼트는 --a3-7/--page 짝으로 실제 대비를 확보했다. 원본에 없는 Sankey·mindmap은 동일한 얇은 선/평면 문법으로 연결점을 실제 박스 좌표에 연결했다.
- journey 선이 다음 카드 면 아래로 가려지던 문제를 수정하고 실제 카드 폭·높이 및 mood 차이에서 길이와 각도를 계산했다. funnel 글자는 사선 안쪽 여백을 확보했다. dumbbell은 값에 해당하는 수평 위치에 빈 점/채운 점과 위·아래 수치를 함께 놓았다.
- generic dark cover는 page/neutral 면 위 --ink를 사용한다. generic dark 코너의 흰 면이 첫 범례/제목을 숨기던 실제 대비 문제는 --n-2 면으로 고쳤다. 원본 05의 6카드용 흰 코너는 보존했다.
- architecture 최소 8×4의 키오스크/영업 note 간섭은 강한 기존 selector가 compact 규칙을 덮던 원인을 고쳐 12px/label-line으로 해결했다. 최종 측정에서 키오스크 영역 끝 y176.4, 다음 영업 시작 y199.6으로 분리된다.
- padding/margin/gap의 원본 실측 길이는 kit의 공유 --space-N 토큰 52개에 실제 px 값으로 등록하고 foundation 및 요소에서 직접 참조한다. 위치·폭·높이는 도형 geometry로 유지한다.
- foundation의 기본 seat는 전체 슬롯 안에 들어가고 그 안에 정사각 회색 면과 번호를 중앙에 그린다. 이전 1104px 정사각 root가 576px 높이 슬롯을 넘던 문제를 실제 박스 검사로 확인하고 수정했다.
- 주측 독립 browser 검사와 같은 스크립트로 light/dark 각각 513개 케이스의 잘림·겹침 0건을 확인했다. light 대비 후보는 0건이다. dark 12개 후보는 architecture 3개/ribbon 9개의 강조 pseudo 면을 DOM 검사기가 놓친 오탐이다. 실제 PNG 면 RGB(244,127,53), 글자 RGB(24,19,14)를 샘플링한 대비는 6.97:1이다. 근거는 library/contrast-resolutions.json이다.
- 전체 fixture 171개와 foundation 2개를 모드별 173장의 1280×720 PNG로 렌더했다. 요소 56폴더+foundation의 light/dark 폴더 시트는 114장이고, 전체 library PDF는 각 173페이지다. 원본 비교는 replica/조립본 각각 15장이다. 최종 자동 검사 숫자는 automatic-checks.json에 기록한다.

독립 최종 검수자는 foundation/chart-stack/funnel/journey/mindmap의 10개 최종 폴더 시트를 한 장씩 열람하고, native fixture 30장과 새 Chromium 렌더 및 시트 tile 30개에서 RGB 차이 0을 확인했다. 이 5폴더의 최소·중간·전체 41개 고유 칸 × 2모드에서도 경계·겹침 문제 0건이다. 보고서는 library/independent-final-review.md에 있다. 마지막 조립본 비교 15장의 SHA256은 주측 개별 시각 검수에서 승인한 파일과 전부 동일하다.


## 주 에이전트 최종 통합 검수

초기 재조립의 큰 배치 차이를 그리드 제약으로 남긴 판단을 철회하고, 원본과 각 페이지를 개별 비교해 원본 비율·위계·연결선·표 구조로 수정했다. 최종 비교 PNG의 SHA-256을 시각 검수 기록에 묶어, 검수 뒤 파일이 바뀌지 않았는지 확인했다. 폰트 정보가 없는 원본은 실제 로드한 제공 글꼴로 맞췄으며, 남는 글자 윤곽·작은 아이콘·대비 보정의 차이는 위 기록을 따른다.

최종 소스의 180개 페이지를 브라우저로 다시 렌더해 저장 PNG와 픽셀 단위 일치를 확인했고, 모든 페이지의 1280×720·폰트 로드·텍스트 경계·요소 박스·텍스트 캡슐의 실제 글리프 중심을 검사했다. 라이브러리는 라이트/다크 최소·중간·12×6 검사와 CSS 범위/계약 검사를 수행했다. 가상요소·그라디언트로 인한 대비 후보는 실제 화면을 확인해 별도 기록했다.

모범 card-4의 원문 ✹와 모범 callout의 배치는 같은 마크업·데이터 보존 요구를 우선했다. 다른 아이콘은 빈 Lucide slot이며, 다른 fixture의 최상위 배치는 12×6이다. 페이지 PDF는 마지막 PNG로 무손실 조립하고 PDF를 다시 래스터화해 같은 픽셀인지 확인했다. 라이브러리 PDF는 최종 fixture 전체를 포함한다.

`lead-integration.json`은 독립 최종 검사와 대비 판정, `lead-final-files.json`은 최종 파일 크기·SHA-256의 기준이다.
