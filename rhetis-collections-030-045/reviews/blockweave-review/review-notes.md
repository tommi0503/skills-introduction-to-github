# blockweave 검수 기록

대상은 045 회사소개서 19장이다. 모든 원본은 작업 자료로만 취급했다. 원본 19장별 유형과 계약 매핑은 inventory.md에 있다.

## 수행과 확인

1. README 전체 및 계약을 읽고 원본 19장을 각각 확인했다. replica를 먼저 제작한 뒤 실제 Chromium에서 19장을 1280×720으로 렌더했다. 원본 | replica 비교 이미지를 각 장별로 열어 배치·줄바꿈·표·연결선·색을 검토했다.
2. 원본과 replica의 반복 형태를 design-language.md에 정리한 뒤 56개 요소와 foundation을 제작했다. 샘플 CSS는 복제하지 않았다. 지정된 모범 fixture는 데이터·마크업을 보존하고 data-el 접두어만 변경했다. 모범 폴더의 추가 fixture도 보존했다.
3. 공식 preview.py로 light/dark HTML을 만들고 각 fixture의 12×6 및 주석에 선언한 최소 크기를 실제 브라우저에서 렌더했다. 요소별 시트는 모든 fixture를 포함하며 왼쪽은 12×6, 오른쪽은 최소 칸이다. PDF는 모드별 185 fixture 페이지이다.
4. 같은 foundation과 요소 CSS만으로 19장을 다시 조립했다. 페이지별 별도 요소 CSS는 없고, 12×6 배치와 원본 팔레트·타입 스케일·미리보기 글꼴만 지정했다. 조립본 비교 19장을 각각 열어 검토하고 CSS로 고칠 수 있는 차이를 요소에 반영했다.
5. 초기 원본 재현과 통합 비교 후 15장 조립본의 동일성이 부족하다는 지적을 받았다. 큰 차이를 그리드 한계로 수용했던 판단을 철회하고, 원본/replica 실측으로 19장을 다시 검토하는 최종 수정 묶음을 수행했다. 15장의 318×130 패널, 170px 중심원,94px 노드와 연결선을 복구하고 다른 장의 박스화·도형 크기·구분선·칩·타이포도 고쳤다. 마지막 CSS를 다시 포함해 PNG/PDF/비교 PNG를 갱신했다. 자세한 기계 검사와 PNG 크기·해시는 automatic-checks.json, page-checks.json, library-checks.json에 있다.

## 수정한 문제

- 상위 최종 검수에서 발견한 10장 아래 원형 범례와 제목 위치, 13장 조용한 넓은 패널의 좌우 54px 여백·키 라벨 굵기, 14장 카드 내부 상단 정렬, hub-4 최소 6×3 상단 초과, 단계 날짜 대비를 마지막 한 묶음으로 수정했다. 다른 장의 디자인은 이 묶음에서 변경하지 않았다.
- 표의 행 높이·열 폭, 긴 사업명 줄바꿈, 숫자 정렬, 큰 설명문 밀도를 조정했다. 최종 시각 검수에서 금융표 상단 헤더 우선순위, hub 패널 제목의 align-self 잔류, 일정 본문 크기·소유 영역, funnel 최소 칸의 숫자 크기, 중첩 sankey의 줄 분리, metric 내부 spark의 폭0, 3원 venn의 강조 텍스트 대비 회귀를 추가로 수정했다. replica 10장의 중복 범례를 제거하고 점 위치를 선 데이터와 일치시켰다.
- 15장의 환형 연결 방향 화살촉을 단순 도형으로 구현했다. 단계형 카드가 마지막 단계에서 상단을 벗어나지 않도록 단계 수에 따라 전체 상승량을 제한했다.
- line/area는 숫자 데이터에 반응하는 CSS anchor 연결을 사용한다. 표시된 특정 fixture 값만 하드코딩하지 않았다. radar의 링·polygon·축은 같은 정사각 좌표계를 쓰며 범례는 위쪽 독립 영역에 둔다.
- minimum 칸에서 timeline 긴 note, radar 축·범례, list 첫 행, venn 중앙 텍스트, cycle 하단 노드가 겹치거나 초과하던 문제를 수정했다. 두 집합 venn은 이름을 바깥 엽에 놓고 core를 중앙 렌즈에 분리한다.
- 원본 강조색은 라이브러리에 저장하지 않았다. 작은 글자의 강조는 --a1-8 등 대비가 높은 역할을 사용하며, fill과 on-text를 짝지었다. 라이트·다크 통합 대비 검사에서 실제 저대비 항목을 수정했다.
- preview.py의 전역 .frame, small 스타일이 계약 내부에 새던 문제는 생성된 미리보기 wrapper 선택자만 좁혀 해결했다. 컬렉션 요소를 도구 버그에 맞춘 값으로 왜곡하지 않았다.
- 영어 의미 없는 샘플 문구는 모범 fixture 외에서 한국어 비즈니스 문장으로 바꾸었다. code는 Nanum Gothic Coding 실제 파일도 로드했다.

## 원본과 남는 차이 / 판독과 결정

- 원본의 정확한 폰트명이 이미지에 기록되어 있지 않아 README 글꼴 중 Pretendard Variable을 선택했다. 실제 woff2 파일을 로드했지만 글리프 폭·획과 일부 줄바꿈은 원본과 차이가 있다.
- 사진, 서명, 복잡한 이미지 및 상표 이미지 자리는 요청대로 연한 회색 단색 placeholder이다. 단순 도형, 표, 그래프, 업무 아이콘은 HTML/CSS/SVG와 Lucide 형태의 선 아이콘으로 그렸다. 원본 전체를 배경 이미지로 사용하지 않았다.
- replica는 원본의 절대 위치를 따른다. reassembled는 12×6 그리드와 중첩 split/stack 및 요소 내부 여백으로 원본 기하를 맞췄다. 그리드라는 이유로 큰 위치·크기 차이를 그대로 수용하지 않았다. 일부 글리프 폭·줄바꿈과 1–10px 수준 간격 차이는 남아 비교 이미지에 공개했다. library의 최소 칸에서는 type step과 설명 밀도를 조절한다.
- 원본 17장의 원은 94%를 차트 점유율로 오해하기 쉽다. 네 사분면은 역량 아이콘 영역, 94%는 중앙 재계약 KPI로 해석했다. 따라서 94%짜리 donut으로 그리지 않았다.
- 12장은 실제 세 원의 교집합을 mask/clip으로 구현하고 A/B/C/D 표기와 오른쪽 문자 칩을 복원했다. 13장의 서비스·성과는 명칭을 포함해 card name/note 구조에 넣었으며 폰트 폭 차이로 일부 줄바꿈이 달라진다.
- 08장과 11장은 동일한 hub 계약을 쓰되 .core.on의 채움과 기본 core의 선형 표현으로 구분했다. 11장의 흰 패널과 파랑/진한 아이콘 원, 하단 매출 칩을 복원했다. Lucide에서 원본과 완전히 같은 아이콘을 찾을 수 없는 일부 사업·인재 아이콘은 가장 가까운 업무 아이콘으로 택했다.
- 18장은 큰 두 개의 흰 card 안에 pill/metric/logo-group/prose를 각자의 data-el과 완전한 계약 마크업으로 중첩했다. 상하 3열, 세로 점선, 라벨과 수치 행을 복원했다. 10장은 실제 숫자 기반 area와 quiet line을 겹쳐 점·선을 복원하고 y축 값과 표 caption을 구성했다. 최종 원본 동일성 검수에 따라 표준 legend 계약을 plot 아래에 놓고, 회색 매출·파란 재계약률의 원형 키를 복구했다. chart-area의 aria-label은 chart 제목이며 범례 데이터는 별도 legend에 남긴다.
- 원본에서 작은 문구의 정확한 판독이 어려운 부분은 원본의 사업·조직 문맥에 맞는 한국어 설명으로 채웠다. 특히 표의 세부 주석, 사업 설명 반복 문구는 내용의 법적 정확성을 주장하지 않는 예시 데이터이다. 읽을 수 없는 글자를 가짜 선으로 대체하지 않았다.
- 원본의 파란색은 replica와 조립본의 미리보기 팔레트에만 있다. 라이브러리 시트는 README 기준 팔레트이므로 다른 색으로 보이며, collection CSS에는 page/ink 외의 원본 색 리터럴이 없다.
- CSS anchor와 shape를 지원하는 최신 Chromium에서 검수했다. 구형 브라우저에서 동일한 선 연결을 보장하지 않는다. 곡선 교집합에는 polygon fallback도 있다.

## 제출물 기준

페이지 PNG는 모두 1280×720, 좌우 비교 PNG는 2560×720이다. 요소별 시트는 모든 fixture를 포함하는 1280×(384×fixture 수) PNG이므로 페이지 PNG와 높이가 다르다. PDF는 렌더된 PNG를 묶어 각 페이지 비율을 유지한다. zip 제작·무결성·push·실제 재다운로드 검사는 상위 통합 작업에서 수행한다.

## 최종 경계 정합

08·09·11·12·19장의 요소 루트에 있던 상단 음수 margin을 0으로 옮기고 foundation의 구성 recipe에서 body 위쪽 경계를 각각 28·45·16·8·10px 확장했다. body 아래 padding이 기존 6행 트랙의 높이·위치를 보존하며 다른 형제 요소는 foundation의 배치 top으로 보정했다. 새 CSS로 실제 Chromium 재렌더한 다섯 장은 수정 전과 변경 픽셀 0이며, 모든 data-el 박스가 body 경계 안에 있다. 수치와 이미지 해시는 boundary-checks.json에 기록했다. 페이지의 디자인이나 콘텐츠는 변경하지 않았다.


## 주 에이전트 최종 통합 검수

초기 재조립의 큰 배치 차이를 그리드 제약으로 남긴 판단을 철회하고, 원본과 각 페이지를 개별 비교해 원본 비율·위계·연결선·표 구조로 수정했다. 최종 비교 PNG의 SHA-256을 시각 검수 기록에 묶어, 검수 뒤 파일이 바뀌지 않았는지 확인했다. 폰트 정보가 없는 원본은 실제 로드한 제공 글꼴로 맞췄으며, 남는 글자 윤곽·작은 아이콘·대비 보정의 차이는 위 기록을 따른다.

최종 소스의 180개 페이지를 브라우저로 다시 렌더해 저장 PNG와 픽셀 단위 일치를 확인했고, 모든 페이지의 1280×720·폰트 로드·텍스트 경계·요소 박스·텍스트 캡슐의 실제 글리프 중심을 검사했다. 라이브러리는 라이트/다크 최소·중간·12×6 검사와 CSS 범위/계약 검사를 수행했다. 가상요소·그라디언트로 인한 대비 후보는 실제 화면을 확인해 별도 기록했다.

모범 card-4의 원문 ✹와 모범 callout의 배치는 같은 마크업·데이터 보존 요구를 우선했다. 다른 아이콘은 빈 Lucide slot이며, 다른 fixture의 최상위 배치는 12×6이다. 페이지 PDF는 마지막 PNG로 무손실 조립하고 PDF를 다시 래스터화해 같은 픽셀인지 확인했다. 라이브러리 PDF는 최종 fixture 전체를 포함한다.

`lead-integration.json`은 독립 최종 검사와 대비 판정, `lead-final-files.json`은 최종 파일 크기·SHA-256의 기준이다.
