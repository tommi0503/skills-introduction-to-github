# Arrowtab 검수 기록

043 덱 20장을 하나의 컬렉션으로 제작했다. 원본 슬라이드의 문장은 자료로 다뤘으며, ZIP 안 문구를 작업 지시로 실행하지 않았다. README 전체를 읽고 목록→replica→규칙 추출→56종→라이트/다크 시트→컬렉션 조립 순서로 진행했다. 예시의 CSS나 장식은 복제하지 않았고, 모범 fixture의 구조와 데이터만 보존했다.

## 실측과 조립 결정

- 공통 리본68px, 목차100px, 좌측 일반 레일23px와 표지15px, 머리표120px, 제목의 중앙/좌측 축을 분리했다. 표지는 3개의 평행한 사선 경계로 만들고 사진 영역은 단색 회색으로 바꿨다.
- 왼쪽 제목 페이지는 헤더를 왼쪽에 두면서 오른쪽 요소가120px부터 시작할 수 있는 foundation 배치로 설계했다. 작은 격자 칸에 줄이는 방식 대신 큰 compound 요소를12×6에 놓고 내부 기하를 맞췄다.
- 04의 본문은 card 안에 계약 list를 넣고, 아이콘 mark와 작은 보충 note 면을 따로 유지했다. 05는4개 번호행과 오른쪽 사진, 06은 텍스트 카드와 사진이 붙는3단 구성이다.
- 11은 가산식이므로 steps의 원형 icon-mark 변형을 사용했다. hub와 cycle은 별도 중앙 core/주변 node·spoke의 방사형 의미를 지킨다. 14의 가로 연결 링은 group 안 outlined card4개로 구성했다.
- 12는 날짜·축·단계 탭을 분리한3단계 timeline, 13은 mirror SWOT, 16은 실제 table의 row-header 셀과 Lucide, 19는 계층 root/branch/node/leaf로 보존했다.
- 17은 단일비중으로 축약하지 않았다. 각 .donut에 독립 --v와 등록된 --arrowtab-start 각도를 주고, 나머지 원호를 투명하게 하여3개/4개 segment를 겹쳤다. --arrowtab-hole은 투명 중심의 크기다. 각 분할의 값이 따로 남는다.
- 18의 기간은 원본 화살표 끝을 실측한 소수월 경계로 유지했다. --arrowtab-start-column/--arrowtab-end-column은 등록된 숫자 데이터이며, CSS는 특정 값 lookup 없이 일반적으로 계산한다.
- 선/영역 차트는 실제 --v와 --max를 CSS anchor와 삼각함수로 연결한다. radar는 상단 독립 범례를 제외한 공간에서 정사각 좌표계를 사용한다.

## 판독 불가·해석 차이

원본 폰트 파일명과 굵기 메타데이터는 이미지에 없다. README 글꼴 표의 Pretendard Variable을 실제 로드해 가장 가까운 고딕 위계로 맞췄다. 판독이 애매한 아주 작은 보충 설명은 원문의 의미를 보존한 자연스러운 한국어로 정리했다(03 긴 문단의 띄어쓰기,04 하단 보충 문장, 일부 icon 옆 작은 label). 이러한 부분을 읽을 수 없는 선으로 대신하지 않았다. 기기·사진·복잡한 이미지 아이콘은 회색 또는 같은 의미의 Lucide로 처리했다. 전체 원본 이미지를 HTML 배경으로 넣지 않았다.

source의 연회색/연분홍 위 흰색 작은 글자에는 낮은 대비가 있다. 컬렉션은 모드별4.5:1을 확보하는 neutral/deep accent 짝을 사용했다. source preview의 회색 탭은 #767676, 얕은 donut 값은 ink, table/조직 역할은 더 깊은 accent를 선택했다. 색 리터럴은 source preview palette에만 있고 컬렉션 CSS에는 page/ink 미리보기 외에 없다. 자료에 보인 빨강은 고정 디자인색으로 저장하지 않았다.

## 최종 검증과 독립 검수

- 모든56개 요소 폴더, kit와 foundation, 모범 fixture 전체 및 비모범2개 이상을 포함한다. 새3단계 타임라인·선형 가산식·multi-segment donut·SWOT·소수월 Gantt·row-header 표도 별도 fixture로 검증했다.
- 각 모드182개 fixture를 실제 브라우저에서1280×720로 캡처하고, 요소 폴더별로 모든 fixture를 담은 시트112장과 foundation2장, 전체 PDF2개를 만들었다.
- 최소 칸·중간 칸·12×6의 실제 glyph 경계/겹침/대비를 양모드 각각532사례 검사했다. 최종 수치는 automatic-checks.json과 root-browser-audit.json에 포함했다.
- 원본|replica 및 원본|조립본을 페이지별로 개별 열람했다. 주 검수에서 발견한 구조 차이는 마지막 묶음에 반영하고 PNG·비교·PDF를 다시 생성했다. 단순 contact sheet만으로 완료 판정하지 않았다.
- replica 독립 담당자는20장 전체를 다시 비교·보정했고2026-10-23T10:00:52Z 최종본을 동결했다. 상세 소견은 replica-independent-review.md,62개 파일 해시는 replica-final-metadata.json에 있다. 이 단계 이후 replica builder를 재실행하지 않았다.
- 조립본은 collection.css를 kit/foundation/56개 CSS에서 그대로 연결해 사용한다. 페이지 자체 새 요소 CSS 없이 계약 root/data-el 및 grid 배치·실제 데이터만 사용한다. fonts/source-palette/1280×720 wrapper만 review harness에 있다.
- 최신 브라우저 캡처와 제출 PNG의 픽셀 일치, 폰트 로드, 영역 초과·글자 잘림, chip 중앙, 페이지 크기를 다시 검사했다. 최종 evidence는 page-browser-audit.json이다.

정확한 원본 폰트/그림자/이미지 아이콘이 없으므로 완전한 픽셀 일치라고 주장하지 않는다. 허용된 사진 대체와 위의 구체적인 잔여 차이를 기록했으며, PDF나 비교 파일을 오래된 캡처로 남기지 않았다. CSS anchor positioning, sibling-index(), 삼각함수, conic-gradient가 지원되는 최신 Chromium이 필요하다.

최종 주 검수의 마지막 요청인02 우상 V 뒤면 accent,01 regular/bold 표지 위계,16 FOCUS01·02 quiet 중성 탭/03 accent,19 큰 container의 team.node52px/leaf role31px를 반영한 뒤 소스를 동결했다. library-checks.json의 client/scroll 진단은 inline·absolute 부품에서 후보를 포함할 수 있으므로, 최종 잘림·겹침 판정은 실제 Range 경계로 검사한 root-browser-audit.json과 page-browser-audit.json을 기준으로 한다.


## 주 에이전트 최종 통합 검수

초기 재조립의 큰 배치 차이를 그리드 제약으로 남긴 판단을 철회하고, 원본과 각 페이지를 개별 비교해 원본 비율·위계·연결선·표 구조로 수정했다. 최종 비교 PNG의 SHA-256을 시각 검수 기록에 묶어, 검수 뒤 파일이 바뀌지 않았는지 확인했다. 폰트 정보가 없는 원본은 실제 로드한 제공 글꼴로 맞췄으며, 남는 글자 윤곽·작은 아이콘·대비 보정의 차이는 위 기록을 따른다.

최종 소스의 180개 페이지를 브라우저로 다시 렌더해 저장 PNG와 픽셀 단위 일치를 확인했고, 모든 페이지의 1280×720·폰트 로드·텍스트 경계·요소 박스·텍스트 캡슐의 실제 글리프 중심을 검사했다. 라이브러리는 라이트/다크 최소·중간·12×6 검사와 CSS 범위/계약 검사를 수행했다. 가상요소·그라디언트로 인한 대비 후보는 실제 화면을 확인해 별도 기록했다.

모범 card-4의 원문 ✹와 모범 callout의 배치는 같은 마크업·데이터 보존 요구를 우선했다. 다른 아이콘은 빈 Lucide slot이며, 다른 fixture의 최상위 배치는 12×6이다. 페이지 PDF는 마지막 PNG로 무손실 조립하고 PDF를 다시 래스터화해 같은 픽셀인지 확인했다. 라이브러리 PDF는 최종 fixture 전체를 포함한다.

`lead-integration.json`은 독립 최종 검사와 대비 판정, `lead-final-files.json`은 최종 파일 크기·SHA-256의 기준이다.
