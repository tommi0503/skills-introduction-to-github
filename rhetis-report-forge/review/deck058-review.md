# Deck 058 검수 기록

- 범위: `public/reference/058/slide_01.png`–`slide_20.png` 전체 20장.
- `rhetis-kit-reference.zip`의 README 계약을 끝까지 읽고, 슬라이드 재현 소스는 새 작업 폴더의 독립 덱 파일로 작성했다. 원본의 설명 문구는 화면 콘텐츠로만 취급했다.
- 구현: `src/decks/d058.tsx`. 공통 Base, Brand, AccentTitle, Check, Insight 컴포넌트 및 슬라이드 데이터로 구성했다. 원본 이미지를 화면 배경으로 사용하지 않았다.
- 폰트: 실제 로드된 Pretendard variable(400–850). 원본 폰트명 메타데이터가 없어 시각 비교로 선택했다. 영문 글꼴의 곡선 및 자폭, 일부 한국어 줄바꿈은 원본과 미세하게 다르다.
- 배경색 #f6f6f6, 강조 #ff282b, 검정 #222. 고정 캔버스 1280×720.

## 진행한 검수

1. 원본 20장을 `view_image`로 한 장씩 확인했다.
2. 실제 Chromium으로 전체 20장을 렌더하고 원본/구현 비교 이미지 20장을 각각 확인했다. 첫 비교에서 제목 자폭·위치, 표지 영문 자간, 성공방정식 Insight 배경을 보정했다.
3. 두 번째 전체 렌더 후 20장 비교를 각각 다시 확인했다. 본문 자간 확대가 사이클 설명을 세 줄로 만드는 것을 발견해 원복했다. 공통 제목을 47px로 미세 조정하고, 표지 행간의 자동 오탐을 해소하고, 08의 원본에 없는 하단 장식 선을 제거했다.
4. 세 번째 최종 렌더에서 수정된 01·03·06·08·14 비교 이미지를 다시 확인했다. 모든 PNG가 최종 소스를 반영한다.

## 자동 검사 결과

최종 `node scripts/render.mjs 058` 성공. `review/audit-058-replica.json` 기준 20/20장의 크기는 1280×720, 모든 장에서 400·700 Pretendard 로딩 확인, text/chip 화면 초과 및 스크롤 넘침 0건이다. 20개 PNG 실측 크기 집합은 `{(1280, 720)}`이다. `npm run build` 성공했다. Lucide 번들의 비파괴적 use-client/청크 크기 경고가 있다.

판독 불가능해서 새로 지어낸 본문은 없다. 원본의 오탈자 또는 붙여쓰기는 대체로 유지했다(예: 06 가운데 설명의 ‘과정을보여주세요’). 가장 어려웠던 부분은 원본 폰트의 정확한 자폭 추정과 사진 배경이 사라진 08의 전경 대비 판단이었다.
