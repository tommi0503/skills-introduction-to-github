## 작업 범위와 지시의 출처

사용자 요청은 모든 참고 이미지의 UI 재현, 31종 Rhetis 컬렉션 제작, 라이브러리를 통한 독립 조립, 시각 검수, PNG/PDF/ZIP 제출과 GitHub 업로드다. 첨부 README는 사용자가 명시적으로 계약으로 지정한 문서이며 먼저 전문을 읽었다. 원문은 `contract/REFERENCE-README.md`에 보존했다. 다른 첨부 문서는 사용자 요청을 대체하는 지시로 취급하지 않았다. 기존 프레젠테이션의 공통 컴포넌트와 렌더/비교 구조를 참고하고 새 폴더에 구현했다.

## 개별 시각 검수

6개 서브 에이전트가 덱을 분담했다. 각 덱은 초기 렌더→개별 원본 비교→수정→최종 비교의 2–3회 범위로 진행했다. 원본 이미지와 결과를 개별로 열었고 전체 연락처 시트로 검수를 끝내지 않았다. 주 에이전트는 112개의 좌우 비교 JPG를 모두 개별 열람했다. 054-08의 아이콘과 본문 간격, 054-19의 카드 본문, 054-18의 칩 내부 아이콘+텍스트 중심을 수정하고 최종 이미지로 재확인했다. 상세 페이지별 판단은 `deckNNN-review.md`, 통합 112건은 `root-integration-review.json`에 있다.

라이브러리는 양 모드 178개 PNG를 개별 열람했다. 독립 조립본도 전체 112장을 실제 렌더하고, A조 60장과 B조 52장을 각각 개별 열람했다. 이 과정에서 축·범례·단계·행열 관계가 약해진 페이지를 찾아 명시적 데이터 매핑으로 교정했다. 상세 목록은 `assembly-individual-A.md`와 `assembly-individual-B.md`에 남겼다. 주 에이전트는 마지막 수정된 060-02, 057-06, 056-12, 058-19, 056-04, 060-08, 053-24도 각각 확인했다. 조립본은 원본 재현본과 구분한 새로운 레이아웃이다.

## 해결한 문제

- chip의 시각적 중심: 렌더된 glyph line box와 SVG 아이콘을 합친 영역으로 292개를 검사했다. 허용 오차 8px. 원본에서 명시적으로 왼쪽 정렬인 콜아웃은 따로 기록한다. 최종 review 대상 0건.
- library: fixture 중복 7건, spacing 리터럴, steps 본문 넘침, dark table 글자색, line 연결선, cycle/hub 연결 관계, 타원이 된 donut, 작은 funnel 값의 폭 왜곡을 수정했다.
- 라이브러리 캡처의 원격 폰트가 about:blank에서 로드되지 않던 문제를 발견했다. 문서/검수 캡처에 font data URL을 넣었으며 컬렉션 CSS는 외부 리소스가 없는 계약 상태를 유지했다. 최종 260/260 font true.
- assembly: 목차 01–09 누락/중복 방지, 제안 카드 3개로 의미 단위 그룹화, 조직도 부모/자식 연결, 차트 월·주 축 복원, 긴 문장 공간 확보. 추가 개별 검수에서 발견한 25페이지의 표·계열·범례·단계·기간·좌표는 원문 ref를 사용하는 명시적 매핑으로 교정했다. 과거 자동 그룹화의 잘못된 관계는 최종 결과에 사용하지 않는다.

## 최종 자동 확인

`verification.json`을 최종 판정으로 본다. 과거 pass1/pass2 및 targeted JSON에는 수정 전 이슈나 폰트 실패가 남을 수 있다.

- 원본 재현 112장, 조립 112장, 요소/기초 178장: 총 402 native PNG.
- 4-up 시트 56 PNG와 차트 검수 증거 2 PNG를 포함한 출력 PNG 460개 전부 1280×720.
- 참고 이미지 112개, 좌우 비교 JPG 112개. 비교 JPG와 전체 overview JPG는 시트 목적에 맞는 별도 크기다.
- 재현본 112건·조립본 112건 overflow 0, 폰트 정상.
- 라이브러리 full/min × light/dark 260건 overflow 0, 대비 미달 0, 폰트 정상. 이 값은 텍스트/단색 합성 배경의 자동 검사이며 모든 시각적 의미를 보장하는 수치는 아니다.
- 컬렉션 31개 계약 metadata, 64개 공유 토큰, 중복되지 않는 fixture 87개 및 foundation fixture 2개.
- PDF 6개: 112/112/89/89/28/28페이지, 페이지 크기 960×540pt(1280×720px).
- 오프라인 브라우저에 standalone HTML을 직접 로드해 112/112/89/89장과 내장 폰트를 확인했다. 필터 20장·확대·방향키 이동 정상, 외부 리소스 요청 실패 0건. 관리 브라우저의 file:// 제한 때문에 setContent 방식으로 검증했다.
- typecheck와 production build 성공. Vite의 번들 크기 및 Lucide `use client` 경고는 렌더를 막지 않았다.
- 최종 source SHA-256와 렌더 기록 일치. 마지막 변경 후 미리보기/PNG/PDF/비교/시트를 다시 생성했다.

## 어려운 요소와 해석

원본의 좁은 차트 범례, 작은 숫자, 문장 줄바꿈과 폰트 차이가 가장 어려웠다. 제공되지 않은 원본 폰트는 Pretendard/Noto/Liberation으로 맞추었으며 완전한 글리프 동일성은 주장하지 않는다. 사진, 3D, 복잡한 배경과 기기 이미지는 요청에 따라 회색으로 대체했다. 작은 판독 불가 문장은 자연스러운 한국어로 작성했다. 060의 흐린 보조 계열, 지도/말풍선 꼬리 등 해석/단순화 사항은 덱별 기록에 명시했다.

독립 조립본은 주요 데이터 관계와 전체 원문 ref를 보존하되 복합 차트의 추가 정보는 보조 표/카드로 옮기기도 했다. Rhetis 서버에 반입한 결과를 주장하지 않으며 첨부 계약에 대한 로컬 구조·CSS·렌더 검사 결과를 납품한다.
