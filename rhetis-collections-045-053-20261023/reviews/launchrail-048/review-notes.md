# Launchrail 048 검수 기록

## 범위와 자료 해석

048 덱의 원본 30장을 각각 열어 분석했다. 첨부 README를 끝까지 읽은 뒤 inventory → 독립 replica → 디자인 언어 → 56개 계약 요소 → 재조립 순서로 제작했다. 이미지 안의 문구는 자료로만 사용했다. 원본 이미지를 페이지 배경으로 깔지 않았다.

## 최초 비교에서 거절된 실제 문제

최초 재조립은 전 30장이 시각 검수를 통과하지 못했다. 공통 폴더 프레임의 겹친 탭, 아이콘 원, 점선, 본문 정렬과 크기가 달랐고, 19의 4구간 도넛·21의 순환 관계·26의 대각선 수상 구조·30의 연락처 캡슐을 과도하게 단순화했다. 자동 검사 0건은 시각 일치의 근거가 아니었다. 초기 소스는 production의 revisions/v1-visual-baseline에 보존했다. 이 차이를 계약상의 불가피한 추상화로 면제하지 않는다.

## 계약 유지와 구현 결정

본문은 `.slide > .page > .body`의 12×6 그리드를 유지한다. body의 직접 자식에는 grid-column/grid-row만 둔다. 각 슬롯의 foundation `.group` 안에 계약 요소를 놓고 element.json에 선언한 private 숫자 토큰으로 요소의 x/y/폭/높이와 기존 parts의 좌표를 공급한다. 새로운 페이지 CSS, 페이지 번호 선택자, 원본 이미지 전체 배경을 사용하지 않는다. 공유 타입과 팔레트 값은 호스트 style 데이터가 공급한다.

처음의 반응형 규칙이 측정된 데이터 배치에 다시 영향을 주는 cascade 충돌은 기본 구현을 CSS layer로 분리해 고쳤다. 부모 요소의 `.name` 규칙이 중첩 list의 이름에 배경/여백을 덧씌우던 문제도 list 내부에서 명시적으로 해제했다. 새 데이터 API는 계약 마크업을 유지하며 본문 텍스트를 숨겨서 잘림을 회피하지 않는다. 중복된 차트 계열 이름은 위나 오른쪽에 같은 이름이 실제로 보이는 경우에만 중복 시각 표기를 없앤다.

56개 요소 및 모범 fixture의 마크업/데이터는 유지한다. 비모범 fixture의 오래된 ul/li 목록은 현재 `.list > .item > .name/.note`로 정규화했고 중첩 요소에 자기 data-el을 부여했다. 같은 데이터를 복제했던 비모범 fixture는 멤버·긴 문구·유효 변형을 다르게 구성했다.

## 글꼴·아이콘 결정과 검수 상태

원본 글꼴의 파일 이름은 이미지로 확정되지 않아 README에 있는 Pretendard Variable을 실제 로드했다. 제목 굵기 800과 역할별 이름/본문/수치 굵기를 픽셀로 재측정했고 소스의 21/23px 크기는 호스트의 타입 값으로 공급한다. 손으로 받친 수익 아이콘, 핀, 전화/메일, 전구, 트로피/별은 같은 뜻의 단순 SVG/Lucide 구조로 그렸다. 이것은 사진 자리의 회색 치환과 구분한다.

모든 원본|replica 및 원본|재조립 비교 이미지를 각각 한 장씩 열어 다시 검토했다. 남은 차이가 보이는 경우에는 완료로 판정하지 않는다. 이 문서의 수정 목록은 작업 내용을 기록하며 동일성 승인을 대신하지 않는다. 최종 상태는 마지막 통합 검사와 주 에이전트의 마지막 PNG 시각 검수로 확정한다.


## 계량 타이포 보정

03 제목의 원본 crop(140,96,210,50)은 ink 190×38px였다. Pretendard Variable 800, 42px, 자간 +0.5px의 F1은 0.966으로 기존 44px/850보다 근접했다. 컬렉션 CSS는 합법 단계인 var(--type-44)를 유지하고, 원본 검수용 호스트가 --type-44:42px를 공급한다. 같은 방식으로 --type-22:21px, --type-24:23px를 공급한다. README는 font-size의 토큰 이름을 정하며 호스트 타입 값 자체를 고정하지 않으므로, 공식 library 시트는 contract/type-steps.json의 원래 값으로 별도 검수한다. --type-42 등의 새 불법 단계는 만들지 않았다.

## 전체 native fixture 기능 재검수

전체 fixture의 라이트/다크 패널을 개별 판독하면서 기본 slope와 dumbbell이 같았던 구현, timeline.alt의 조상 anchor 실패, pyramid-4 상단 note의 clip-path 잘림을 찾았다. 기본 slope는 실제 두 시점 값의 높이를 잇는 선으로, timeline은 축 위 점과 카드까지 닿는 줄기로 고쳤다. 피라미드는 색면만 잘라 문구의 실루엣 잘림을 없앴다. balance의 수평/좌중량/우중량 빔과 연결고리를 각각 보았으며, lines-12의 인접 44→44가 끊기지 않는 것도 확인했다. chart-stack은 12개 막대·5계열·5색 범례를 같은 데이터로 넣고 다섯 번째 계열을 n-4/ink로 제공한다. README에 없는 a5/a5-on 참조는 없다.

마지막 비교 PNG 판독에서 22 번호의 사각 코너, 23 마지막 제목의 불필요한 2행, 26 하단 점선의 잘못 남은 회전, 30 이메일의 과도한 라틴 폭을 추가로 발견했다. 번호는 원으로 되돌렸고, 23은 원본 폭에 맞는 Pretendard 22/700을 호스트 타입 값으로 공급한다. 26 분기에는 대각 방향과 교차하는 dash gradient 및 각도 없는 하단 경로를 적용했다. 30은 라틴 본문을 Pretendard 400으로 실측 원문 폭에 맞추고 세로 구분자를 글리프가 아닌 1px 선으로 그렸다.

## 마지막 렌더 스냅샷

컬렉션 56요소·175fixture, 양모드 350개 fixture와 7,750개 정수 그리드 크기의 자동 검사 결과는 0 findings다. replica 30장과 reassembled 30장 모두 1280×720이며 마지막 브라우저 검사에서 잘림·영역 초과·폰트 실패를 찾지 못했다. 최종 CSS/HTML/폰트는 render-source-audit.json과 일치하고 review/collection은 제작 소스와 byte 단위로 일치한다. native 시트는 요소 56개와 foundation의 양모드 114장이며 전체 PDF는 각각 177개의 native fixture 페이지다. 각 요소의 실제 시각 판독 근거와 해당 PNG 해시는 library-visual-audit.json에 남겼다. 이 자동 검사 수치는 원본 동일성 승인을 뜻하지 않으며 주 에이전트의 최종 PNG 개별 승인 전에는 업로드 완료로 판정하지 않는다.
