# 주 에이전트 통합 검수

## 범위와 지시 구분

업로드한 디자인 PNG는 5개 덱·121장이다. 005번의 01–07이나 009번의 09 이후는 첨부되지 않았으므로 만들지 않았다. 원본 121장 전부 1280×720이며 `source-manifest.json`에 해시를 저장했다. 첨부 README는 사용자가 계약으로 명시한 토큰/요소 형식에만 적용했다. 이미지 안의 작성 안내는 재현할 콘텐츠로 취급했다.

작업은 별도 `rhetis-report-suite-project/`에 만들었다. 기존 `presentation5-clone`의 데이터/공통 렌더러 분리와 실제 Chromium·해시 검수 구조를 참고했다. 기존 프로젝트 소스는 수정하지 않았다. 담당 5명은 덱별 데이터와 기록을 분리했고, 1명은 컬렉션을 맡았다. 주 에이전트가 공통 렌더러·실제 컬렉션 재조립·최종 통합과 배포를 담당했다.

## 개별 시각 검토

각 담당자는 모든 원본을 개별 열람하고, 자신의 덱을 2–3회 비교·수정했다. 자동 캡처 중단은 같은 회차를 재개하여 처리했다. 모든 최종 페이지를 실제 브라우저로 캡처했고, 각 원본과 결과의 비교 파일을 만들었다. 재조립본도 121장 전부 개별 열람했다(005 23장, 006/007 60장, 008 30장, 009 8장). 주 에이전트는 대표 비교와 모든 통합 수정 지점을 별도로 확인했다. 시트는 탐색에만 사용했다.

주 에이전트가 직접 확인한 개별 원본/결과 비교: 005의 08/15/22/24, 006의 01/14/18/28, 007의 01/12 및 최종 22 지도, 008의 01/19/24/30, 009의 01/04/06/07. 이후 최종 단일 PNG에서 재조립 005-08/22, 006-04/06/15, 007-25/26, 008-22/25/28과 원본형 009-03을 다시 확인했다. 최종 파일 해시와 이전 개별 검토 파일의 픽셀 일치 여부는 `production-pixel-verification.json`으로 연결한다.

컬렉션은 31개 요소·79개 fixture를 최소 칸과 전체 칸, light/dark에서 검사했다. cover 최소 칸 중복을 제외한 314개 PNG는 모두 1280×720이다. 담당자는 모든 요소의 개별 화면을 보고, 주 에이전트는 line chart 연결, dark pricing, dark matrix 등 핵심 결과를 확대 확인했다. 정적 계약과 실제 글자 대비·겹침 검사는 `library/` 기록에 있다.

## 통합 수정과 해석

- Lucide의 SVG 크기·색상 전달 오류를 고쳐 실제 요청한 속성이 적용되도록 했다. chip은 Canvas 실제 글자 경계로 시각적 중심을 맞춘다.
- 한국어 폰트 em box의 여분 공간을 글자 잘림으로 오인하지 않도록 실제 글리프 경계를 측정했다. 폰트 준비 확인도 기본 ASCII가 아닌 실제 문자열로 수행한다.
- `₩` 등 별도 Unicode subset에 대해 캡처 전에 필요한 글꼴과 실제 글자를 명시적으로 로드했다.
- 긴 브라우저 세션의 반복 navigation에서 간헐 타임아웃이 발생해, 동일 브라우저 문서에서 같은 렌더러로 독립 슬라이드를 순차 표시한다. 갤러리와 단일 URL 이동은 별도 production 검증한다.
- 최종 CLI의 `--production` 불리언 처리 오류를 발견해 수정했다. `final`은 production 외에는 거부하고, 실제 `/assets/…` 빌드 엔트리 로딩을 확인한다. 수정 전 캡처를 production으로 오인해 제출하지 않았다.
- 재조립 카드가 containment와 flex 충돌로 지나치게 좁아지는 문제를 고쳤다. 보조 문구는 원본의 좁은 칸에서 쓰던 강제 개행을 접고, 문자량을 기준으로 4열에 나눠 겹침을 해소했다.
- 이미지 자리는 실제 `image-frame`과 `seat`로 보존한다. 008-25의 원형 프로필 자리도 검출한다. 사진·복잡 삽화·기기 화면의 재질은 연회색 단색이다.
- 조직도는 첫 root와 나머지 네 branch로 조립하여 개발팀 등이 누락되지 않도록 했다. 다섯 Venn 항목과 다섯 donut 항목은 계약의 멤버 한도에 맞춰 3+2 모듈로 나눴다.
- 006-14는 120명의 연령별 인원 10/50/30/10/20을 보존하고, 원 비율만 합계에 맞춰 그린다. 숫자를 백분율로 잘못 표기하지 않는다.
- 006-15는 원본에 실제 숫자가 표기된 자사 7,000과 경쟁사 2,500을 이름과 연결한다. 숫자 없이 그려진 중간 막대의 폭에서 값을 추정해 표시하지 않는다.
- 007-23은 원본의 `00%` 템플릿임을 설명한다. 007-25의 양쪽 선 그래프 수치와 오른쪽 두 시리즈를 모두 보존한다. 007-27의 기간은 기획 1–3월, 설계 3–6월, 홍보 6–11월, 운영 9–12월, 보수 11–12월이다.
- 007-26의 연속형 열 구역을 matrix로 정리할 때 VIP는 고빈도·고금액(오른쪽 위)에, 일반 고객은 저빈도·저금액에 두어 축 방향과 의미를 일치시켰다.
- 008-19의 불필요한 core를 없애 ‘비용’ label을 드러냈다. 008-22에는 20%/10%/70%의 보조 donut 3개를 배치했다. 짧은 ‘상무’ 같은 실제 문구도 보존하며, 008-28의 제목 칸이 좁아지지 않도록 했다.
- 007-22 지도는 직접 만든 지리 SVG를 사용한다. 최하단 677.95px로 본문 안에 수용했고 최종 PNG에서 확인했다. 원본과 투영·해안선의 세부 차이는 남는다.

## 산출물의 차이와 한계

원본 재현본은 원본의 자유 배치·테두리·강조·색과 타이포 위계를 최대한 맞춘다. 재조립본은 의미 데이터와 텍스트, 이미지 자리를 Rhetis 12×6 그리드에 넣은 별도 표준 구성이다. 원본의 모든 장식과 좌표를 그대로 복사하는 버전은 재현본이다. 원본 편집 파일의 폰트 메타데이터가 없어 서체는 추정이며, Lucide 및 직접 SVG의 세부 획은 원본과 다를 수 있다. 원본에 없는 31개 요소는 같은 언어로 확장 설계했다. 판독이 불가능하거나 해석이 갈리는 부분은 담당 기록에 명시했다.

컬렉션 소스는 외부 자산 금지 계약에 따라 폰트 파일이나 `@font-face`를 포함하지 않는다. 검수 환경의 실제 설치된 Noto Sans CJK KR로 렌더했다. 앱은 fontsource/로컬 의존성의 실제 폰트를 로드한다. line chart 연결은 최신 Chromium의 CSS anchor positioning을 사용한다.

최종 자동 검증·PNG 해시·빌드 정합성은 `verification.json`, ZIP 내부 검사는 `package-preflight.json`, GitHub에서 내려받은 실제 ZIP 검사는 `github-download-verification.json`을 따른다. GitHub 검사는 ZIP 생성·업로드 후 수행하므로 저장소에 별도 기록한다.
