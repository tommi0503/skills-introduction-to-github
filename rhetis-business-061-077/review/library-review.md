# Business Prism 라이브러리 제작·검수 기록

README.md를 끝까지 읽고 taxonomy 2026-10-18.1 및 공유 토큰/타입 단계 계약에 맞춰 독립적인 새 컬렉션을 작성했습니다. `samples/atlas`, `samples/miri`는 계약 파일 형식과 fixture 사용 구조를 확인하는 데만 이용했습니다. 기존 컬렉션 디자인과 CSS는 복사하지 않았습니다.

## 결과

- 컬렉션: `collection/business-prism/`.
- 키트: 필수 공유 토큰 63개, 색상 토큰은 라이트/다크 모두 공급.
- foundation: 1280×720, 12열×6행 본문, head/lead, cover, top/foot/rail, group/stack/split, gray seat. fixture 3개.
- 요소 31개, 요소 fixture 80개. 기본/강조/quiet/line/5 tone, 가로·세로 차트/단계, 세부 멤버수, 장문 예시를 포함합니다.
- `light.html`, `dark.html`: 제공된 `tools/preview.py`를 그대로 실행하여 생성했습니다.

- 선언 최소칸 PNG 160장: 각 모드 요소 fixture 80개. foundation은 이미 12×6이므로 별도 최소칸 이미지를 중복 생성하지 않았습니다.
- 모든 위 PNG는 1280×720입니다.

## 디자인 해석

061의 정돈된 중립색 판넬과 테두리, 064·065·071의 블루 보고서 위계, 066의 주황 보조 강조, 069의 인덱스와 가는 선, 073의 시안 계열 데이터 강조, 077의 직선적 기하학 언어를 공통 기반으로 해석했습니다. 서로 다른 8개 덱을 한 컬렉션으로 정리하기 위해 본문은 거의 각진 패널, 강조는 네이비·블루·시안, 주황은 변화·단계 표시라는 일관된 역할을 부여했습니다. 모든 덱의 개별 장식과 색을 동시에 섞지 않았습니다.

사진·화면·복잡한 그래픽은 번호가 있는 회색 seat로 남겼습니다. 커버의 사선 prism은 자체 CSS 도형입니다. 원본 전체 이미지를 배경에 사용하지 않았고, 요소 CSS에는 이미지·외부 URL·font-face가 없습니다.

## 실제 브라우저·폰트

실제 Chromium 브라우저로 83 fixture 각각을 라이트/다크 렌더했습니다. 최종 PNG는 긴 시트를 잘라낸 상태가 아니라 fixture 한 장씩 독립된 1280×720 viewport에 넣고 두 번의 animation frame을 기다린 다음 저장했습니다. 마지막 CSS가 반영된 전체칸 166 PNG를 다시 확정했습니다.

호스트에서 `@font-face`를 주입해 Pretendard Regular 400, SemiBold 600, Bold 700, Gmarket Sans Bold 700의 실제 제공 WOFF/WOFF2를 로드했습니다. 폰트는 base64로 호스트에 전달하여 네트워크에 의존하지 않았고, `document.fonts.ready` 및 각 `document.fonts.check()`를 확인했습니다. 라이브러리 자체에는 font-face를 넣지 않았습니다. 결과는 `library-final-render.json`에 기록했습니다.

## 시각 검수와 수정

전체칸 라이트 83장과 다크 83장을 각각 개별 이미지로 열어 글자·중앙 정렬·연결선·테두리·원형·내부 여백·색 역할을 확인했습니다. 최소칸은 실제 브라우저 자동검사와 대표 요소의 개별 이미지를 추가 확인했습니다. 연락처 시트만으로 검수를 끝내지 않았습니다.

1. 첫 검수: 선차트의 CSS anchor 연결이 잘못 교차하는 문제, 순환/허브 노드 angle 계산의 문법 오류, 8개 장문 목록의 세로 초과, 3집합 벤 다이어그램 하단 초과를 발견했습니다.
2. 두 번째 검수: 데이터 선의 양방향 연결, 노드 수별 원주 배치, 조밀한 목록의 타입/간격 단계, 벤 도형의 높이 기준 크기를 수정했습니다. 계층도 root가 모든 분기를 가로지르도록 명시적 열 수도 보완했습니다.
3. 통합 확인: 허브 선이 노드 안의 텍스트를 가로지르지 않도록 시작부를 마스킹했고, preview 도구의 전역 `.frame`/`small` 스타일이 이미지 프레임 크기와 지표 단위 색상을 바꾸지 않게 요소 범위 안에서 보완했습니다. 해당 수정 후 최종 독립 렌더를 다시 저장했습니다.

chip·pill·badge는 flex 정렬과 실제 글자의 시각적 중심을 확인했습니다. 체크·숫자·화살표는 CSS와 텍스트 기반이며, 목록 숫자는 CSS counter로 생성합니다. 좁은 칸에서 fig/name은 유지하고, kick 이후 note를 순서대로 줄이거나 숨깁니다.

## 자동 검사

- 정적 계약: 31개 필수 계약 id, 최소 2 fixture, fixture root 하나, 최상위 grid 선언, data-el, 클래스 화이트리스트, 색·굵기 리터럴 금지, 허용 type 단계, 요소별 container query, 외부 리소스 금지를 검사했습니다. 오류 0건. `library-contract-checks.json`.
- 실제 텍스트 경계: 선언 최소칸에서 표시된 모든 텍스트 노드의 Range를 요소 경계와 비교했습니다. 두 모드 모두 초과 0건. `library-minima-checks.json`.
- 대비: 실제 계산된 글자색과 조상 배경을 alpha 합성하여 28px 미만 4.5, 28px 이상 3의 대비를 검사했습니다. 두 모드 모두 실패 0건. `library-contrast.json`.
- 원시 scrollWidth/scrollHeight 로그는 `library-light-checks.json`, `library-dark-checks.json`입니다. 이 값에는 노드 경계 바깥에 의도적으로 그린 화살표·데이터 점·연결선·체크 marker가 포함됩니다. 이를 실제 텍스트 잘림으로 집계하지 않았고 별도의 Range 경계 검사와 개별 시각검수로 구분했습니다.
- PNG 크기: 전체칸·최소칸 326장 모두 1280×720. source SHA-256은 정적 검사 JSON에 기록했습니다.

## 어려웠던 요소와 판단

- 선차트: 계약이 HTML point만 허용하므로 SVG를 삽입하지 않고 네이티브 CSS anchor로 인접 점을 연결했습니다. 최신 Chromium에서 검증했습니다. 구형 브라우저 지원을 실제로 시험하지 않았습니다.
- 순환·허브·계층도: 이미지에 같은 구조의 모든 멤버 수가 있지는 않아, 직선·직사각형·정확한 중앙 정렬이라는 공통 언어로 3~6개 노드 및 2~4개 분기를 설계했습니다.
- 밝은 시안/주황: 원본의 작은 흰 글자 대비를 그대로 옮기면 계약의 대비 기준과 충돌할 수 있어, 라이브러리의 해당 solid tone은 어두운 글자를 사용하도록 정했습니다. 개별 원본 슬라이드의 정밀 재현과 컬렉션 공통 규칙은 분리했습니다.
- 작은 원본의 불명확한 문구를 라이브러리에 복제하지 않았습니다. fixture 내용은 자연스러운 한국어 사업 문장과 명시적인 수치로 새로 작성했습니다.

Rhetis 원본 importer/intake 실행 환경은 이 ZIP에 포함되지 않았습니다. 제공 계약 파일에 대한 정적 검사와 실제 Chromium 렌더 검사를 완료했으며, 실제 서비스 반입 통과를 실행했다고 주장하지 않습니다.

## 통합 검수 후 cycle 보완

주 에이전트 통합 검수에서 6멤버 cycle의 화살표가 모두 오른쪽을 향해 순환 의미가 약해지는 점을 확인했습니다. cycle 전용 CSS의 화살촉만 수정하여, 각 노드 사이의 링 중간 위치에 두고 타원 링의 시계방향 접선에 맞게 회전했습니다. 계약 클래스·fixture 구조·다른 요소 CSS는 유지했습니다. 3멤버/6멤버 × 라이트/다크 4장만 실제 폰트로 다시 렌더하고 개별 시각 확인했습니다. 마지막 보완은 `library-cycle-final-render.json`과 `library-light/dark-026/027.png`에 반영되어 있습니다.
