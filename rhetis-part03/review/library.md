# Rhetis Report 라이브러리 검수

README.md 전문 및 taxonomy/kit-tokens/measure/type-steps 계약을 읽고 `rhetis-report` 컬렉션을 별도로 제작했다. 기존 atlas/miri의 폴더·fixture 마크업 구조는 형식 참고로만 재사용했고, 요소 CSS 및 foundation 디자인은 새로 작성했다.

## 디자인 해석

첨부한 009·011·014·015·017·018·020·021 몽타주를 전부 확인했다. 서로 다른 팔레트가 포함된 자료를 하나의 컬렉션으로 통합하기 위해 009의 형광 라임 강조, 가는 먹색 테두리, 밝은 회색 패널을 중심 언어로 삼았다. 014의 명확한 수치 위계, 015의 절제된 장표 선, 018의 세이지 및 020의 파랑을 보조 토큰으로 해석했다. 장식 사진·인물·로고는 회색 seat로 표현했다. 다크 모드는 짙은 포리스트 차콜과 읽기 쉬운 밝은 잉크를 별도로 지정했다.

## 구성과 자동 점검

- 계약 요소 31개, 요소 fixture 87개, foundation fixture 2개(cover 및 seat).
- 필수 공유 토큰 누락 0개. 색 토큰 모두 light/dark 정의.
- 요소 CSS font-size는 허용 `--type-N` 토큰만 사용. 폰트 크기 숫자 리터럴 0개.
- 모든 요소 규칙은 해당 collection data-el root에 범위를 제한했다.
- 본문 메타데이터와 fixture의 중첩 list/tag/stat/plan에도 data-el을 유지했다.
- 공식 preview.py로 light 및 dark 시트를 생성했다.
- 실제 Chromium에서 89개 fixture를 light/dark 각각 렌더했다. 전체 크기(12×6)에서 scrollWidth/scrollHeight 초과 0개.
- 모든 fixture를 6×3, 3×6, 6×6, 12×3, 12×6 순으로 검사하여 실제 견디는 첫 크기를 min 주석에 기록했다. 55개는 6×3, 12개는 3×6, 10개는 6×6, 1개는 12×3, 3개는 12×6이 필요했다. 조밀한 퍼널 5/6단계와 요금제 3개 병렬은 의도적으로 큰 칸을 요구한다.
- 선언한 최소 크기에 대한 최종 light/dark 자동 검사 초과 0개.
- 라인 차트는 CSS anchor positions로 실제 --v 지점을 연결한다. 동률 구간도 수평선으로 처리했다.

## 시각 검수 및 수정

카드 3개 강조형, 12포인트 선 차트, cycle 3–6개 구성, hub, pricing을 개별 렌더로 확인했다. 초기에 수평 막대 8개, 수직 steps 4개 및 gauge의 아래쪽 선이 영역을 초과하여 간격·패딩·선 위치를 수정했다. 선 차트의 단절된 수평 조각을 실제 점 사이 연결로 교체했다. 마지막 수정 후 시트를 재생성하고 재렌더했다.

## 판단 및 제한

이 컬렉션은 서로 다른 8개 덱의 공통 보고서 문법을 통합한 것으로, 모든 덱의 색상을 단일 스타일에 동시에 복제하지 않는다. 커버 장식, 문서에 없는 31개 요소의 세부 형태와 한국어 예시 문장은 계약에 맞춰 설계했다. 촘촘한 장문 데이터·여러 병렬 요금제는 최소 크기 주석을 지켜 배치해야 한다. 원본 폰트 파일은 제공되지 않았으므로 실제 환경의 Noto Sans KR와 Arial fallback을 공유 토큰에서 지정했다. 원본 장표 재현 검수와 라이브러리 조립 검수는 전체 프로젝트 검수 기록에 별도로 포함한다.

## 최종 대비 보완

실제 Chromium의 계산된 텍스트색·배경색을 사용해 `tools/contrast.mjs`로 전체 fixture를 점검했다. 미리보기의 전역 `small` 색상이 수치 단위에 침투하던 부분을 요소 범위 안에서 `color: inherit`로 고쳤다. 라임 강조 카드·필·목차·매트릭스의 note/kicker는 밝은 다크 모드 본문색 대신 해당 강조 배경의 잉크 토큰을 사용하도록 수정했다. 피라미드 최상단 설명도 같은 원칙을 적용했다. 타임라인은 선택한 점만 라임이므로 설명과 날짜에는 원래의 다크 모드 본문/보조 잉크를 유지했다. 요소 `data-el` 범위와 공유 토큰 사용 원칙을 그대로 지켰다.

최종 측정 결과: light 대비 실패 0개, dark 대비 실패 0개 (`review/library-contrast.json`). 기준은 28px 미만 4.5:1, 28px 이상 3:1이다. 대비 수정 후 공식 도구로 두 미리보기를 다시 생성하고, 전체 178개 PNG 및 선언한 최소 크기 검사를 다시 실행했다.


## 요소별 두 번째 fixture 보완

최종 계약 검사에서 fixture가 한 개뿐이던 8개 요소를 확인하여 각각 의미 있는 두 번째 변형을 추가했다. delta는 처리 기간 단축, flowchart는 세로 분기 및 재합류, image-frame은 이미지 두 개 병렬, legend는 차트 없는 두 계열 범례, matrix는 다른 강조 사분면과 사업 위험 판단, pricing은 단독 연간 기관 요금제, tag는 문장 내 highlight 중심 변형, versus는 강조 방향을 바꾼 2항목 비교를 보여 준다. 새 fixture는 모두 보수적으로 12×6 최소 칸을 선언했으며 실제 브라우저에서 검사했다. 기존 81개 최소 크기 분포에 새 12×6 fixture 8개가 추가되었다.

최종 전체는 **31개 요소 / 요소 fixture 87개 / foundation 2개 = 89개 fixture**, light·dark 합계 **178개 PNG**이다. `tools/validate-library.py`의 staticFailures는 빈 배열이며 각 요소의 fixture 개수는 모두 2개 이상이다. 두 공식 미리보기를 재생성하고 대비 및 최소 칸 검사를 다시 실행했다. 이미지 프레임은 받은 칸을 정확히 채우도록 width/height를 명시해 중립 preview wrapper와 클래스명이 같은 경우에도 안전하게 렌더한다.
