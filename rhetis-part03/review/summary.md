# 최종 검수 기록

첨부 README는 사용자가 지정한 라이브러리 계약으로 적용했다. 첨부 이미지의 글자는 구현할 콘텐츠이며 도구 실행 지시로 해석하지 않았다. 기존 저장소의 작업을 보존하고 `rhetis-part03/` 독립 폴더에서 작업했다.

## 범위

009 6장, 011 14장, 014 20장, 015 15장, 017 14장, 018 12장, 020 8장, 021 1장: 총90장. 원본 파일명과 순서를 유지했다. 009는 첨부된09–14페이지만 재현했으며 없는 앞부분은 만들지 않았다.

## 개별 비교와 통합 검수

6명 이내로 담당 덱/파일을 분리했다. 담당자가 모든 원본을 개별 열람하고 실제 Chromium으로 렌더한 각 장을 원본과 나란히 열어 비교했다. 덱별 디자인 비교·수정은2–3회 내에서 수행했다. 주 담당자는009 6개 원본/결과를 모두 개별 비교했고, 각 덱의 최종 결과와 대표적인 표지·표·차트·조직도·긴 문장 화면을 확대해 통합 검수했다. 연락처 시트만으로 개별 검수를 대체하지 않았다.

1차 비교 후 긴 인용문 개행/패널 초과, 강조pill 여백, 제목 위치와 글자 폭, 조직도 대비, 차트 눈금 및 테두리를 수정했다. 통합 자동검사에서 확인한 글리프 메트릭과 텍스트 프레임 차이는 글자가 그려지는 위치를 유지한 채 프레임 크기를 보정했다. 최종production 빌드의90개 PNG를 새로 생성했고 글자 프레임·화면 영역·chip 크기·폰트 로딩 오류는0건이다.

라이브러리 계약 정적 검사에서8개 요소의 두번째 fixture 누락을 발견해 서로 다른 변형을 추가했다. 최종31개 요소 모두2개 이상fixture, 요소87개+foundation2개=89개fixture다. 선언한 최소 크기에서 라이트/다크 영역 초과0건. 실제색 대비 검사에서 강조표면의 보조문구와 단위색 문제를 보정했으며 최종 양 모드 대비실패0건이다.

조립본은 기본컬렉션 CSS와 계약마크업을 사용하되 페이지 `.overrides`로 원본 배치 데이터를 유지한다. 좁은요소에서 보조문구를 숨기는 반응형규칙이 고정장표에도 적용되는 것을 발견해 조립어댑터에서 문구를 보존했다. 실제 로드한 로컬폰트와 세로정렬을 확인하고90장PNG+90페이지PDF를 렌더했다. 화면 밖으로 나가는 텍스트0건이다.

## 원본과 남는 차이 및 판단

- 사진·인물/복잡한 삽화·3D·기기화면·지도·복잡한 증서는 요청대로 연회색단색placeholder다. 원본이미지 전체를 결과캔버스에 넣지 않았다.
- 014의 네온 곡률과 빛번짐, 일부 로고/아이콘, 021의 둥근장식 타이틀 글꼴은 근사다. SVG/CSS로 가능한 단순도형·도표·배경곡선은 직접 구현했다.
- 원본폰트파일/폰트명 메타데이터가 없어 실제 로드한Pretendard Variable/Inter와시스템 글꼴로 근사했다. 라이브러리의Noto Sans KR/Arial fallback 사용은키트토큰에 명시했다.
- 원문에있는PLACEHOLDER 문장·임의년도·WEAKNES 같은오기는 원본콘텐츠로 유지했다. 글자를 선으로 대체하지 않았다. 상세판독·대체결정은덱별기록을 따른다.
- 8개 덱을1개 컬렉션으로 통합하므로 라임강조, 가는먹색선, 밝은회색패널을공통문법으로 삼았다. 이미지에없는 요소와 fixture용 한국어 비즈니스문장은 계약에따라 설계했다.
- 조립본 글자크기는허용된 `--type-N` 단계로정규화하므로 원본재현본과 일부크기·줄바꿈이 다를수있다. 배치·색 override를제거하면라이브러리기본표현으로 바뀐다.
