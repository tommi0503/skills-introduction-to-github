# 덱 09·10 개별 검수 기록

- 담당 소스: `src/decks/d09.tsx`, `src/decks/d10.tsx`; 각 10장, 총 20장.
- 계약: 첨부 README.md 전체를 먼저 읽었다. README는 사용자 요청에 따라 적용하는 라이브러리 형식 계약으로 취급했으며, 샘플 디자인은 차용하지 않았다.
- 원본 20장 모두 `view_image`로 개별 열람했다. 결과는 실제 Chromium 브라우저에서 각 슬라이드 URL로 별도 렌더했다.
- 렌더 크기: 20장 모두 1280×720. 원본 이미지를 결과 페이지의 배경으로 사용하지 않았다.

## 검수 과정

1. `round1`: 20장 원본/결과 비교 이미지를 각각 열어 배치, 여백, 글자 크기, 차트와 표를 비교했다. 폰트 경로와 alias 문제로 대체 폰트가 사용된 사실을 확인했다. 이 회차를 최종 폰트 판정에는 사용하지 않았다. 도넛 수치 라벨, 오른쪽 설명 위치, 목차 위치와 표의 줄바꿈을 수정했다.
2. `round2`: Pretendard Variable 이름으로 시험했으나 font-not-ready가 기록되었다. 공통 폰트 alias와 Vite 파일 접근 설정 수정 후 정상 Pretendard 이름으로 통일했다. 이 회차는 폰트 장애 진단 기록으로 남긴다.
3. `round3`: 정상 로드된 폰트로 전체 20장을 다시 렌더하고, 각 원본/결과 비교 이미지를 개별 확인했다. 표지와 헤더의 타이포 크기, 계획 3열의 행간, 막대 바닥의 직각 모서리, 표의 긴 문장 줄바꿈을 최종 보정했다. 최종 보정을 반영해 같은 회차를 다시 렌더했고 수정한 페이지의 비교 이미지도 열어 확인했다.

최종 자동 검사: 덱 09 10장, 덱 10 10장 모두 findings 0; 브라우저 예외 0; 폰트 요청 실패 0. 결과는 `review/round3/09-replica.json`, `review/round3/10-replica.json`에 있다.

## 판단과 어려웠던 부분

- 모든 작은 문구가 원본 크기에서 충분히 읽혀 임의의 가짜 문구나 선을 넣지 않았다.
- 원본 폰트 메타데이터가 없어 글리프 형태를 완전히 일치시키는 것은 한계가 있다. 실제 폰트를 로드해 크기·무게·자간·행간을 맞췄다.
- 09-03의 고밀도 선형 그래픽은 단순 도형 한두 개가 아닌 그래픽 이미지로 판단했고, 10-04의 복합 삽화와 함께 회색 placeholder로 대체했다.
- 차트는 이미지가 아닌 DOM/CSS/SVG와 데이터로 구현했다. 표와 진행률, 머리말, 프레임은 재사용 가능한 로컬 컴포넌트와 공통 UI primitives를 사용한다.
