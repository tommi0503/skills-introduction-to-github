# 덱 19·22 제작 및 검수 기록

- 범위: 원본 JPG 덱 19의 10장, 덱 22의 10장. 전체 20개 원본을 개별 이미지로 열어 확인하고 작성했다.
- 계약: 첨부 `rhetis-kit-reference.zip/README.md`를 끝까지 읽었다. 예제 컬렉션의 시각 디자인을 가져오지 않았다.
- 소유 소스: `src/decks/d19.tsx`, `src/decks/d22.tsx`.
- 원본 1600×900 좌표를 0.8배로 변환하여 모든 페이지를 1280×720으로 구현했다. 화면 비율 및 기울기 변형은 없다.
- 텍스트와 사진 좌석은 공용 `ui.T`, `ui.PH`를 통과한다. 재조립 모드에서도 동일한 원본 데이터가 라이브러리 텍스트·프레임 요소로 렌더된다.

## 시각 검수

폰트 서버의 `/@fs` 403 때문에 발생한 최초 두 번의 시도는 유효 시각 검수에서 제외했다. 부모 에이전트가 Vite 경로 접근을 고치고 서버를 재시작한 뒤 실제 Anton·Pretendard·Poppins 로딩을 확인한 렌더로 다음 두 번을 수행했다.

1. `renders/round1/replica/19-01.png`부터 `19-10.png`, `22-01.png`부터 `22-10.png`까지 브라우저 렌더. `comparisons/round1/{19,22}/01.jpg`부터 `10.jpg`까지 총 20개 비교 이미지를 각각 열어 원본과 나란히 확인했다.
2. 제목의 위치·크기·굵기, 이름 강조, 텍스트 줄바꿈, 콘텐츠 높이, 하프톤 별의 방향과 비율을 보정하고 `round2`를 렌더했다. `comparisons/round2/{19,22}/01.jpg`부터 `10.jpg`까지 모두 개별적으로 다시 열어 확인했다. 연락처 시트만으로 검수하지 않았다.

최종 담당 렌더 명령: `node scripts/render.mjs 19 22 --round=round2`.

- 덱 19: 10장, findings 0, 브라우저 오류 0, 폰트 요청 실패 0.

- 20장 모두 브라우저 캔버스와 PNG 크기 1280×720.

- 해시태그·INPUT·OUTPUT·원형 역량 레이블은 flex 정렬로 가로·세로 중앙 배치한 뒤 렌더에서 확인했다.

## 해석·차이·결정

- 모든 인물·사진·기기 화면은 사용자 지시대로 연회색 `#e5e5e5` 좌석으로 대체했다. 투명 인물 컷아웃도 전체 바운딩 박스를 직사각형 좌석으로 표현했다. 이로 인해 원본 사진의 실루엣과 명암은 보존되지 않는다.
- 덱 19의 영문 디스플레이에는 실제 로드한 Anton, 한글에는 Pretendard Variable을 사용했다. 큰 제목의 폭과 높이가 매우 가깝지만 원본 글꼴을 증명하는 메타데이터는 없으므로 동일한 폰트 파일이라고 단정하지 않는다.
- 덱 22의 영문에는 실제 로드한 Poppins 600/700을 사용했다. 원본의 일부 영문 글자 꼴(특히 t, f)과 자간, 별점의 둥근 끝에는 차이가 남는다. 한글 본문도 글리프 폭 차이 때문에 일부 자동 줄바꿈이 원본과 다르다.
- 덱 22의 별은 원본을 붙여 넣지 않고 재사용 가능한 SVG 하프톤 벡터로 그렸다. 원본의 비대칭 점 패턴을 그대로 복제하지는 않는다.
- 읽을 수 있는 문구는 원문을 옮겼다. 덱 22의 PROJECT 01 첫 문구 `위적인 화려함을 걷어내고`는 원본에서 그렇게 읽히므로 임의 교정하지 않았다. 담당 원본에서 완전히 판독 불가능하여 새 문구가 필요한 본문은 없었다.
