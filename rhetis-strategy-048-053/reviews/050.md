# 050 흑백·주황 중간점검 보고서 — 개별 검수

참고 원본: `public/reference/050_1jzmm_흑백_깔끔_중간점검_보고서_안내/slide_01.png`–`slide_20.png` (20장).
구현: `src/decks/d050.js`. 표지·헤더·카드·원형 아이콘·글머리표·체크박스·변화 핀·화살표를 공통 함수로 정의하고 각 페이지는 독립 데이터로 조립했다. 원본 이미지를 결과 페이지 배경에 사용하지 않았다.

## 검수 절차와 결과

- 키트 README 전체를 읽고, 참고 이미지 20장을 먼저 모두 원본 크기로 개별 열람했다. 이미지에 적힌 템플릿 안내 문장은 콘텐츠로 취급했다.
- 실제 Chromium 1280×720 렌더 → 원본/결과 나란히 비교 → 각 장 개별 시각 확인을 3회 수행했다. 연락처 시트만으로 판단하지 않았다. 비교 이미지는 `artifacts/comparisons/050/050-01.jpg`–`050-20.jpg`에 있다. 검토 시에는 각 비교의 원본/결과를 1280px 폭 상하 배치로 다시 열어 확인했다.
- 1차: 공통 렌더러의 0px 높이/음수 높이 선 누락을 찾아 주 에이전트에게 전달했다. KPI 상세 설명 3개, 리스크 설명 1개의 텍스트 영역을 수정했다.
- 2차: 모든 수평·수직·기울어진 선, 글머리표의 실측 지름, 핀 곡선, 차트 기둥 밑면, 실제 폰트 굵기, 작은 선 아이콘을 확인하고 보정했다.
- 3차: 모든 20장을 다시 개별 비교했다. 주황 원/버튼 그림자, KPI 채움의 왼쪽 각진 모서리, 점선 목표 영역, 작은 타임라인 화살표, 원형 지표 그림자를 확인했다. 마지막 보정으로 직선 화살표의 단색 조각을 같은 위치/크기의 CSS `linear-gradient`로 교체했다. 이 마지막 보정의 최종 PNG 반영 여부는 주 에이전트의 통합 렌더에서 확인한다.
- 세 번째 Chromium 렌더 시 PNG 20장 모두 **1280×720**, 텍스트 잘림·페이지 영역 초과 자동검사 **0건**. `document.fonts.ready` 이후에 캡처했으며 로컬 Pretendard variable 폰트의 100–900 실제 굵기를 사용했다. `node --check src/decks/d050.js` 통과.
- 캡슐/버튼의 제목과 숫자는 고정 영역 내부 flex 수직·수평 가운데 정렬로 구현하고 실제 렌더에서 확인했다.

## 해석과 남은 차이

사진 및 사진 속 화면 7개 영역을 사용자 지시에 따라 연회색 단색으로 처리했다(01,02,07의3개,14,15). 나머지 차트·표·도형·텍스트는 모두 HTML/CSS/SVG로 구성했다. 배경 곡선을 직접 그렸으며 화면 회전이나 원본 비율 왜곡을 사용하지 않았다.

원본 폰트의 정확한 이름은 이미지 메타데이터만으로 확정할 수 없어 로드 가능한 Pretendard variable을 사용했고 줄바꿈·굵기·크기·자간을 조정했다. 원본의 작은 아이콘은 동일 의미와 얇은 선 언어로 다시 그렸기 때문에 픽셀 경로가 완전히 같지는 않다. 그 외 사진으로 대체한 영역의 세부 텍스트를 새로 만들지 않았으며 본문에서 판독 불가능해 임의 작성한 문구는 없다.
