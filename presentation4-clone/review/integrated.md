# 주 에이전트 최종 통합 검수

## 범위와 진행
첨부 ZIP의 실제 이미지 43개 덱·77장 전체를 사용했다. Drive는 사용하지 않았고 slides-clone은 확인하지 않았다. CSV의 문구는 원본 참고 자료로만 해석했다. 화면 안의 편집 안내문은 표시할 텍스트이며 작업 지시로 실행하지 않았다.

담당자 3명은 파일과 덱을 분리하여 1·2차 개별 비교를 수행했고, 주 에이전트가 모든 77장에 대해 원본 왼쪽/실제 브라우저 결과 오른쪽의 개별 비교 이미지를 열어 3차 통합 검수를 수행했다. 연락처 시트는 탐색 보조용이다. 덱별 비교·수정은 이 3차 과정으로 제한했다.

## 최종 통합 수정
- p04/s02 Daily Standups 아이콘을 PersonStanding으로 교체했다. p04/s03·s04의 반복/교차 방향 아이콘을 원본처럼 U자 경로와 반대 방향 화살표를 벡터로 구현했다.
- p11/s11의 회사 표시 별을 원본 크기의 8개 방사 벡터 선으로 구현했다.
- p13/s15 및 p32/s05 제목은 좁은 Roboto Condensed 대신 실제 Roboto 700 파일을 로드해 폭을 보정했다. 본문의 Condensed 글꼴은 유지했다.
- p34의 원본 단색을 샘플링하여 공통 단계 색상을 수정하고, s03 화살표 외곽과 s07 단계/접힌 모서리 색을 각각 맞췄다.
- p36/s04의 4개 원형 구간 사이를 방사형 틈에서 원본처럼 수직·수평의 일정한 흰 간격으로 보정했다.
- p39/s06의 둥근 꽃잎 구간을 재사용 가능한 벡터 팩토리로 만들었다. 5개 원의 도형은 각각 45°씩 진행하며 글자와 아이콘은 수직으로 유지했다. 구간 경계의 흰 선도 맞췄다.
- p43/s07의 누적 막대는 마지막 구간의 오른쪽 모서리만 둥글게 처리하여 내부 경계의 불필요한 흰 틈을 제거했다.
- 글꼴 검사에서 document.fonts.load 이후 완료 상태를 즉시 읽는 경합을 발견했다. 실제 파일 요청은 성공했으며 document.fonts.ready와 두 프레임을 기다린 뒤 상태를 검사하도록 수정했다. 실패 판정을 무시하지 않았다.

## 남은 차이와 판독 범위
- 원본 편집 파일과 폰트 메타데이터가 없어 모든 원본 글꼴의 이름을 확인할 수는 없다. 가까운 실제 로컬 폰트를 사용했다. 각 담당 기록에 글꼴 선택과 남은 폭·획 차이를 적었으며 자동 검사에 실제 로드된 face와 굵기를 기록한다.
- Lucide로 표현 가능한 아이콘은 의미와 위치를 맞췄지만 원본의 채운 아이콘이나 세부 획과 차이가 있다. 복합 이미지 아이콘은 단색 회색 placeholder로 처리했다.
- p26/s09·s12, p40/s10, p42/s04와 장식 그래픽 영역은 요청한 #e5e5e5 placeholder로 치환했다. 원본의 흰 글자는 유지하여 일부 페이지의 대비가 낮아졌다. 원본 이미지 전체를 UI에 깔지 않았다.
- p34·p35·p39의 입체 음영/그라데이션은 평면 색과 기본 그림자로 근사했다. p36/s01의 순환 경계, p38의 손으로 그린 불규칙한 모서리·화살표는 벡터/기본 모서리로 근사하여 원본과 미세한 형태 차이가 남는다.
- 차트에 수치가 표시되지 않은 구간은 축과 원본 막대 길이로 추정했다. 정확한 원자료로 해석하면 안 된다.
- 담당자와 주 에이전트가 구현한 일반 문구는 판독 가능했다. 임의 대체 문구는 없으며 원본의 오탈자·예시 문구는 그대로 유지했다. 이미지 placeholder 안의 세부 내용은 구현 범위에서 제외했다.

## 최종 결과 검증
최종 source/renderer/PNG SHA-256 및 각 페이지의 검토 목록은 visual-review.json에, 자동 검사 결과는 verification.json에, ZIP 수량·크기·CRC·SHA-256은 archive-integrity.json에 기록한다. 마지막 통합 수정 후 production 빌드에서 77장 전체를 다시 캡처하고 수정 화면을 개별 재확인한다. 성공 여부는 이 파일들과 실제 명령 실행 결과를 기준으로 판단한다.
