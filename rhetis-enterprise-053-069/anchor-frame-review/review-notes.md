# Anchor Frame 검수 기록

## 범위와 근거

- 대상: 069_1l1vx 덱의 첨부 표지 1장. 이미지 ZIP의 다른 덱과 섞지 않았다.
- README를 끝까지 읽고 replica → 디자인 언어 → collection → library → reassembled 순서로 진행했다.
- 컬렉션: kit 1개, foundation 1개, 계약 요소 56개 전체. 모범 fixture는 지정된 원문의 마크업과 데이터를 유지하고 data-el 접두어만 바꿨다. 그 외 fixture는 멤버 수, 변형과 긴 문구를 포함하며 각 요소 2개 이상이다.
- samples의 CSS나 장식 디자인을 사용하지 않았다. 데이터 마크업을 형식 계약의 입력으로 사용하고 모든 요소의 디자인은 독립적으로 작성했다.

## 원본과 replica

1. 원본을 개별 1280×720 화면에서 확인한 뒤 브라우저 렌더를 나란히 놓고 제목 폭·굵기·베이스라인·프레임 좌표를 비교했다. 초기 Pretendard가 원본보다 좁아 Noto Sans KR를 실제 로드하는 방식으로 교체했다.
2. 강조 제목은 76px/800, 검정 큰 제목은 104px/900, 본문 24px로 맞췄다. 원본의 정확한 폰트명은 이미지에 없으므로 글자 폭과 모양을 기준으로 선택한 근사다. 활자 가장자리와 일부 자간은 원본과 완전히 같다고 보장하지 않는다.
3. 두 건축 사진은 요청대로 연한 회색 단색 placeholder다. 원본 전체 이미지나 사진을 배경으로 깔지 않았다. 프레임·앵커는 CSS 도형으로 구현했다.
4. 제목·설명·회사명·이메일은 판독 가능해 그대로 옮겼다. 판독 불가로 창작한 원본 문구는 없다.
5. 연락처 프레임은 페이지 밖으로 이어지는 선으로 해석했다. 작은 앵커의 세부 획과 화면 밖 잘림은 이미지에서 추정했다.

## 컬렉션과 라이브러리 검수

- 얇은 직각 프레임, 네 귀의 앵커, 큰 좌측 정렬 제목과 좁은 세로 강조선을 기준으로 나머지 56요소를 확장했다. 원형이 의미를 갖는 도넛·벤·동심원 이외에는 사각 문법을 유지했다.
- 색은 자리 토큰으로만 표현한다. 작은 강조 글자는 --a1 대신 --a1-7을 써서 기준 팔레트의 라이트/다크 대비를 확보했다. 실제 원본 색은 replica와 reassembled의 미리보기 style에서만 공급한다.
- preview.py로 라이트·다크 시트를 만들고 모든 fixture를 브라우저에서 렌더했다. 각 요소 폴더의 PNG에는 12×6과 선언한 최소 칸을 나란히 실었다. 전체 PDF는 fixture별 1280×720 페이지다.
- 초기 경계 검사에서 작은 칸의 카드 단위 글자, 게이지, 목록, 도넛 긴 이름, 세로 단계, 긴 본문의 넘침을 발견했다. 컨테이너 글자 단계, 패딩·간격, 중첩 요소의 내재 크기, 최소 지원 칸을 고쳤다. fig와 name은 숨기지 않았다.
- legacy 형식 예시의 ul/li 목록은 비필수 fixture에 한해 현재 .list > .item > .name 계약으로 바꾸고 nested data-el을 붙였다. pricing의 .list.check와 nested tag도 보완했다.
- 선/영역 차트는 live --v 값과 CSS anchor로 그린다. right/bottom의 anchor 좌표 해석을 실제 렌더로 확인해 수정했다. --v를 바꾸면 점·선·영역이 함께 움직인다. 여러 시리즈의 이름은 플롯 위에 둔다.
- 네트워크와 방사 연결선은 길이 단위를 지원하는 hypot()와 atan2()를 사용한다. 브라우저에서 단위 길이를 받지 않는 pow()/sqrt() 표현을 제거하고 해당 요소 PNG/PDF를 다시 생성했다.
- preview.py가 전역 small에 부여하는 회색이 단위 글자에 침투하는 것을 발견해 scoped small의 color:inherit로 차단했다.
- 연속 heatmap은 최대 채움을 40%로 낮추고 글자를 --ink로 유지했다. 어두운 모드의 중간톤 위 작은 숫자 대비가 무너지지 않게 한 판단이다.
- 주의: 모범 card-4의 ✹ 문자는 모범 fixture 원문에 존재한다. “같은 마크업·데이터” 요구를 우선해 원문을 보존했다. 신규 fixture에서 아이콘을 문자로 흉내 내지는 않았다.

## 라이브러리 조립본

- .slide > .page > .body 12×6 그리드에 headline, prose, image-frame만 배치했다. 새로운 페이지 전용 배치 CSS를 만들지 않았다. HTML의 CSS는 컬렉션 토큰·foundation·요소 원본과 타입/팔레트 미리보기 공급값이다.
- 원본의 자유 좌표를 12×6으로 정규화하므로 사진 프레임의 x/y·겹침 정도, 설명과 제목의 간격, 하단 연락처 프레임은 replica와 다르다. 요소 자체의 큰 두 단 제목과 프레임 앵커 언어는 유지했다.
- 원본의 세 번째 연락처 프레임은 조립본에서 별도 배경 도형으로 억지 삽입하지 않고 텍스트로 남겼다. 계약 요소만 쓰라는 조건과 임의 좌표 장식을 만들지 않는 조건을 우선했다.
- 사진 자리에는 번호가 표시된다. 이는 Rhetis seat 계약에 따른 것이며 replica의 무표기 회색 사진 자리와 다르다.

## 검증의 한계

- browser-audit.json: 실제 브라우저의 글자 범위가 소속 요소 경계를 넘는지, 페이지 크기와 글꼴 로딩을 검사한다. geometry 최종 수정 후 PNG/PDF도 다시 생성했다.
- all-sizes-audit.json: 선언한 최소 크기부터 12×6까지의 모든 열/행 조합과 두 모드, 텍스트 대비를 검사한다. 배경이 gradient/pseudo-element인 부분은 DOM 색 계산만으로 완전한 픽셀 대비를 보장하지 않아 별도 시각 검수도 했다.
- 자동 경계 검사는 글자와 도형 사이의 모든 의미적 충돌까지 증명하지 않는다. Rhetis 자체 intake 실행기는 제공되지 않았으므로 공식 반입 통과를 주장하지 않는다.
- 원본 덱 비교는 3회의 제목/폰트/정렬 보정 안에서 마무리했다. 라이브러리 품질 보정은 별도로 진행했다.

## 최종 통합 보정

- 모든 요소 PNG는 최종 통합 규격 1280×720 한 장으로 다시 배치했다. 여러 fixture는 full/min 화면을 원래 16:9 비율로 줄여 격자에 넣었으며 세로로 압축하거나 늘리지 않았다. 시트 HTML과 전체 PDF의 fixture별 큰 화면은 유지한다.
- 조립본의 큰 제목이 마지막 패딩 조정 후 작은 단계로 떨어지는 문제를 통합 검수에서 발견했다. container query가 300px border-box가 아닌 252px content-box를 기준으로 삼는 것이 원인이었다. 큰 제목 조건을 content-height 220px로 보정하고 headline 전체 크기 조합을 다시 검사한 뒤 해당 PNG/PDF와 조립본을 재생성했다.
- 최종 전체 그리드 검사는 9,836개 라이트/다크 크기 조합에서 글자 경계 실패 0건, 대비 실패 fixture 0건이다. 제목 조건 변경 후 별도 all-sizes-headline-audit.json에 headline 크기 조합 재검사를 남겼다.
- 카드의 이름과 설명 길이가 달라도 제목 시작선이 흔들리지 않게 충분한 높이에서는 이름 2줄/설명 3줄 분량의 자리를 일정하게 확보했다. 카드 최소~12×6 조합을 별도 all-sizes-card-audit.json으로 재확인했다.
