# 056 / scanline-rise 검수 기록

## 범위와 산출물

원본 18장, replica 18장, 라이브러리 요소 56개와 foundation, 재조립 18장이다. `inventory.md`에 파일별 페이지 유형과 계약 대응을 기록했다. 모든 페이지는 Chromium으로 1280×720에서 렌더했다. 비교 PNG는 원본과 렌더를 좌우로 붙이므로 **2560×720**이며, 페이지 PNG 및 요소별 시트 PNG는 **1280×720**이다.

## 비교·수정

1. 원본 18장을 개별 확인하고, replica를 모두 실브라우저에서 렌더했다. 페이지별 원본 | replica 비교를 한 장씩 열어 타이포 위계, 제목 위치, 카드 간격, 원형 구조, 표의 행 높이를 확인했다. 잘못 커진 SVG 아이콘, 목차 로고 줄바꿈, 가로 카드의 강제 줄바꿈, 작은 그래프 비례를 수정했다.
2. collection의 라이트·다크 sheet와 최소 칸을 렌더했다. 선/영역 차트의 anchor 연결을 실제 데이터에 맞게 수정하고, 도넛 0·100·여러 멤버, 작은 SWOT, 태그의 intrinsic 크기, 인물·로고의 square seat, 원이 타원이 되는 문제를 고쳤다. 강조 텍스트는 palette의 깊은 단계로 이동했다.
3. 재조립을 페이지별로 원본과 비교했다. stack 안의 크기 소실, 작은 가로 카드의 본문 소실, 긴 note 카드의 header/본문 균형, 작은 hub 글자, 마지막 요약의 배치를 수정했다. 요소 CSS를 수정한 후 library와 재조립을 다시 렌더하여 마지막 수정의 반영을 확인했다. 제한된 전장 비교 과정 안에서 원인 확인을 위한 부분 렌더와 자동 검사는 반복했다.

## 원본과 남아 있는 차이

- 원본의 흐림·입체감이 있는 scanline 배경은 replica에서 연회색 단색 placeholder다. 표지의 신호 막대 외곽은 단순 polygon으로 경계만 보존했다. 라이브러리 foundation에서는 같은 반복선 언어를 평면 선으로 추상화했다.
- 11쪽 기기 화면과 18쪽 사진은 연회색 placeholder다. 11쪽의 기기 외곽은 단순 둥근 직사각형으로 유지했다. library image seat는 계약대로 square placement여서 재조립 사진/기기 비율은 원본과 다르다.
- 원본 글꼴의 메타데이터가 없어 Pretendard Variable을 선택했다. 읽을 수 있는 문장은 보존했으나 원본 font와 줄바꿈의 미세한 차이가 있다.
- 원본의 사업 로고는 복잡한 자산을 사용하지 않고 단순 도형/텍스트로 재구성했다. 재조립의 상단은 foundation의 deck 텍스트다.
- replica의 원형 관계도와 PEST는 원·선·SVG path로 만들었다. 원본과 접선·중심의 아주 작은 차이가 있다. 06쪽의 세부 brace 연결 및 14쪽의 화살표 장식은 간결한 선/화살표로 해석했다.
- 재조립은 계약 마크업과 12×6 배치에 맞춰 재배열했다. 03의 가로 카드, 06의 KPI layer, 09의 mini chart, 15의 이슈 표는 의미와 주요 타이포를 유지하지만 원본의 자유 배치와 정확히 일치하지 않는다. 17의 계단은 요소를 서로 다른 grid-row에서 시작하게 배치했다.
- 08의 막대+선 복합 차트는 재조립에서 막대 요소로 표현했다. 현재 계약에 복합 차트가 없기 때문이다. 10의 4분할 ring은 재조립에서 주요 share 40%의 donut와 설명으로 표현했다. 이 두 경우 원본의 전체 그래픽과 일치하지 않는다.

## 판독 불가·데이터 해석

작은 문구 대부분은 원본 템플릿의 ‘입력해 보세요’ 문장으로 읽혀 그대로 보존했다. 차트의 실제 값이 표시되지 않은 08·09·13쪽 수치는 원본 막대/선의 상대적 높이와 상승 추세를 근거로 근사했다. 재조립에 보이는 55·64·73·85, 25·36·70 등은 원본의 공표 실적이 아니라 **레이아웃 검증용 추정 데이터**다. 11쪽의 10,000건·35,000건은 원본 표시값을 읽어 보존했다. 제목의 ‘2080’·‘20XX’, ‘XX만 건’, ‘노출 노직’ 등 원본 템플릿의 표기는 임의 교정하지 않았다.

## 계약 충돌과 판단

README가 지정한 모범 fixture는 마크업과 데이터의 동일성을 우선했다. 제공된 card fixture 안의 `✹` 문자 아이콘은 README의 새 fixture 아이콘 문자 금지와 충돌한다. 이 mandatory fixture는 원문을 보존했다. 새 fixture의 아이콘은 빈 `data-icon` span이다. 표준 미리보기 도구는 계약 설명대로 아이콘을 점선 링으로 표시한다. 재조립 standalone HTML은 해당 span을 SVG로 채우는 가벼운 표시 스크립트를 포함하며 CSS는 컬렉션 것만 사용한다.

## 자동 검사와 한계

- `replica-audit.json`: 18페이지의 폰트 로딩, 크기, 텍스트 영역 검사.
- `reassembled-audit.json`: 18페이지의 폰트 로딩, 크기, 텍스트 영역 검사.
- `library-audit.json`: 모든 fixture를 양 모드에서 전체 칸과 선언한 최소 칸으로 확인한 568개 state. 마지막 결과의 overflow 목록을 확인한다.
- `visual-alignment-audit.json`: 양 모드 각각 59개 chip/mark의 렌더 텍스트 범위가 칸 안에 있고 중심 오차가 기록되어 있다. 글자의 광학적 중심은 눈으로 함께 확인했다.
- `contract-audit.json`: 56개 폴더, fixture 수, schema, 허용 확장자, 색/폰트/타입/at-rule의 금지 리터럴 검색.

scroll 크기 검사는 실제 glyph의 모든 충돌이나 수학적 색 대비를 증명하지 않는다. 개별 페이지의 시각 검수를 병행했으며, 공식 Rhetis intake를 실행할 수 있는 저장소 환경은 제공되지 않아 본 기록은 공식 반입 통과 증명서가 아니다.
