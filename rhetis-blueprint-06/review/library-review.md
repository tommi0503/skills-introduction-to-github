# Blueprint 06 라이브러리 검수

계약 원문은 첨부 rhetis-kit-reference.zip의 README.md 전체와 contract/taxonomy.json, kit-tokens.json, measure.json, type-steps.json이다. 문서 안의 형식 지시는 사용자가 이 작업의 계약으로 지정한 범위에만 적용했다. samples/atlas와 samples/miri에서는 파일 구조와 class/data-el 계약만 확인했으며 CSS 디자인은 복제하지 않았다.

## 디자인 해석

042의 얇은 보고서 규칙선과 단계형 블루, 044의 조용한 흑백 정보 위계, 045의 코발트 강조와 원형 지표, 046의 라벤더 보조색, 047의 네이비 섹션 필드, 048의 사선 표지 구성을 하나의 새로운 비즈니스 보고서 언어로 묶었다. 원본에서 직접 보이지 않는 31개 계약 요소도 같은 선 굵기·여백·캡슐 레이블·강조 방식을 사용해 설계했다. 사진과 기기 화면 등은 번호가 있는 단색 seat로만 남겼다.

## 구현과 검사

- 공유 토큰 전부를 정의했으며, 23색은 light/dark를 따로 설계했다. 기본 텍스트 색 조합의 최소 대비는 light 5.21, dark 5.28이다.
- foundation 12×6 그리드와 1280×720 고정 캔버스, seat와 사선 표지 fixture를 구현했다.
- 31개 계약 요소, 요소 fixture 73개, foundation fixture 2개다. 카드 9개, pill 4개, timeline 3개 등 주요 변형을 별도 fixture로 포함했다.
- 모든 요소 선택자는 자신의 data-el에 제한했다. 색·폰트·굵기·행간·자간·간격·모서리는 키트 토큰을 사용하며, 크기는 계약 type step을 사용했다.
- Pretendard의 실제 Regular 400 / SemiBold 600 / Bold 700을 로드해 검사했다. 사용하지 않는 등록 굵기가 unloaded인 상태는 실패로 세지 않았다.
- 사용자 지정 preview.py 명령의 light.html / dark.html을 생성했다. 브라우저 검사에서는 각각의 fixture를 독립적으로 전체 칸과 선언한 최소 칸, 라이트와 다크에서 렌더했다. 최종 PNG 300개 모두 1280×720이며 글자 영역 초과·캔버스 초과·사용 폰트 검사 결과 0건이다.
- 31종의 대표 fixture를 개별 PNG로 열어 형태·타이포 위계·축/레이블·조합·명도·번호 seat를 확인했고, 전체 시트만으로 검수를 끝내지 않았다. 자동 결과의 의미와 범위는 tools/collection-check.py에 공개되어 있다.

## 발견해 수정한 항목

1. inline tag의 size containment로 고유 너비가 줄어들던 문제를 해제했다.
2. 최소 칸의 세로 timeline에서 세 번째 note가 영역을 벗어나던 문제를 간격과 단계형 폰트로 고쳤다.
3. 선 차트의 container content box를 이중 차감해 선분이 점에 닿지 않던 계산을 고쳤다.
4. 퍼널 사선 경계가 양끝 텍스트를 가리던 문제를 안전한 내부 여백으로 고쳤다.
5. 허브 연결선이 중심을 지나가거나 텍스트 위로 지나가던 문제를 실제 가로·세로 반경과 노드 경계 계산으로 고쳤다.
6. 6개 이상 agenda와 10행 표의 밀도를 줄여 실제 조립 슬라이드의 칸 크기에 맞췄다.
7. 순환 화살표를 궤도의 진행 방향에 맞췄고, 조직도의 끊어진 수평선을 연속 trunk로 고쳤다.

## 어려웠던 요소와 결정

- chart-line: 계약 구조(.lines > .pt)를 유지하면서 이미지/SVG 없이 임의의 다음 값까지 선분을 연결하려면 다음 값 정보가 필요하다. --v와 함께 namespaced --blueprint-06-next, root의 --blueprint-06-count를 사용한다. 기본값은 element.json의 tokenDefaults에 기록했다.
- cycle/hub: 서로 다른 멤버 수에 맞춰 원본의 원형/방사형 언어를 타원 궤도로 확장했다. 중심과 주변 노드를 숨기지 않고 좁은 칸에서 note만 단계적으로 줄인다.
- 원본은 서로 다른 여섯 디자인 가족이므로 라이브러리 토큰을 모든 원본과 동시에 동일하게 만들 수는 없다. 원본 복제 페이지와 별도로, 새 컬렉션에서는 코발트·네이비·라벤더를 일관된 하나의 언어로 해석했다.
- 라이브러리 fixture의 비즈니스 문구와 수치는 실제 기업 성과 주장이나 판독 결과가 아니라 재사용성을 확인하기 위한 예시 데이터다. 흐릿한 원본 문구를 판독한 것처럼 표시하지 않았다.

최종 CSS와 브라우저 검사 HTML의 일치 여부, 각 소스와 PNG의 SHA-256, 최종 크기 검증은 library-validation.json과 library-render-final/report.json에 기록했다.
