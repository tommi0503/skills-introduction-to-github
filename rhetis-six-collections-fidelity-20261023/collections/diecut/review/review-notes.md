## 글꼴·내용·허용된 차이

원본 14쪽 제목의 실제 폰트 실루엣을 계약 글꼴 후보와 비교했다. 한글을 실제 지원하는 후보 중 SUITE 800이 Pretendard보다 가까웠으며, 이를 kit와 replica의 본문·제목에 실제 로드했다. 큰 Latin 워드마크와 세로 CONTENTS는 별도 Pretendard Variable 토큰으로 둔다. code는 Nanum Gothic Coding을 실제 로드한다. 폰트 파일명 메타데이터를 원본 이미지에서 확인한 것은 아니므로 동일 폰트라고 단정하지 않는다. SUITE의 일부 굵기 선택, 계약의 font-size 단계와 1~수 px의 글리프 차이는 남을 수 있다.

원본의 읽히는 숫자·단계 수·제품명·설명은 보존했다. 5쪽의 연도축 `2080E`는 오기로 보이지만 임의로 수정하지 않았다. 고객 사례의 솔루션 조합과 숫자도 원문대로 두었다. 작은 문장부호·자간 등 판독이 애매한 부분은 자연스러운 한국어 표기로 정리했다. 사업 주장과 숫자의 사실 여부를 검증한 문서는 아니다.

허용된 회색 placeholder에는 제품 렌더, 사진, 복잡한 월계수 이미지가 포함된다. 6쪽 첫 세 로봇팔 이미지 아이콘은 원본에서 서로 다른 복잡한 선화이므로 허용된 회색 placeholder로 두었다. 뒤 세 단순 아이콘은 shield-check·atom·wrench의 실제 Lucide 벡터로 구현하며 도구 선화의 세부 획 차이는 남는다. 원본과 모든 픽셀이 같다고 주장하지 않으며 남은 차이는 비교 PNG에서 확인할 수 있다.

## 컬렉션·재조립 계약

56개 요소, 171개 요소 fixture 및 foundation 2개 fixture를 유지했다. 모범 구성 28개는 접두사만 바꾸고 마크업·데이터를 그대로 보존했다. 원래 group/stack 래퍼·일부 grid 배치·✹ 문자 등 모범 fixture 자체의 일반 규칙 충돌은 사용자의 동일 보존 지시를 우선했다. 비모범 fixture의 중첩 list/prose/tag data-el과 item/name 구조를 정리했다. sample 디자인 CSS는 복사하지 않았다.

재조립 HTML에는 foundation의 `.slide > .page > .body`와 계약 요소·data-el 및 grid 배치·계약 수치 변수만 사용했다. 소스 형상의 복원 규칙은 컬렉션의 foundation과 요소 CSS에 있다. 별도 페이지별 CSS 파일을 추가하지 않았다. `assets/runtime.css`는 실제 폰트·사용자 팔레트·type 단계·1280×720 캔버스만 공급한다. 원본 팔레트는 runtime user style로 공급하며 컬렉션 자체는 색을 소유하지 않는다. 독립 review 배포를 위해 컬렉션 CSS를 assets/collection에 동일 바이트로 복사한다.

## 검증 자료

모든 원본|replica 및 원본|조립본을 개별 PNG로 제공한다. round4-before에는 초기 대표 12·14·15쪽과 원본|이전|수정 비교도 보존했다. 마지막 수정 후 다시 렌더한 페이지 PNG/PDF와 현재 라이브러리 HTML·PNG/PDF를 제출한다. audit JSON은 자동 진단의 원문이고 build-validation.json은 개수·해상도·PDF 쪽수와 복사본 동일성을 기록한다.

자동 overflow의 일부는 12×6 authoring grid 밖으로 전체 캔버스를 사용하는 foundation 조합, 차트 축 레이블, 연결선·pseudo 배경의 내부 경계 초과다. 흰 bar 수치의 배경은 ::before이므로 투명 DOM 배경만 읽는 contrast 진단은 ratio 1로 잘못 보고한다. 원시 경고를 숨기거나 모든 경고를 무조건 오탐이라고 처리하지 않는다. 실제 글자 잘림·중첩은 PNG와 요소별 화면으로 확인하고 수정한다. 정적 체크는 Rhetis intake 자체가 아니며 reference pack에는 intake 실행기가 없다.
