# Afterglow 검수 기록

## 범위와 절차

015 서비스 소개 덱의 9장이 대상이다. README 220줄과 계약 JSON을 끝까지 읽은 뒤 9장 각각을 열어 유형·계약 요소를 정리했다. replica → 디자인 언어 → kit/foundation/56개 요소 → 라이트·다크 시트 → 컬렉션 재조립 순서로 진행했다. 모범 fixture 28개는 data-el 접두어만 바꾸고 원래 마크업·데이터를 보존했다.

## 수정과 실제 확인

- replica에서 외곽 27px, 밝은 1px 프레임, 반경16px, 64px 하단 빛, 상단 세 칸 표기와 실제 문구·줄바꿈을 재현했다. 사진·3D는 연회색 단색 자리다. 각 페이지의 원본|replica 비교 PNG를 개별 열었다.
- 07의 이미지 자리가 제목을 침범하던 문제를 수정했다. 큰 Service는 별도의 글꼴 비교 결과 SUITE Regular 176px를 실제 로드했다. 최종 글자 ink bbox는 원본 (64,130)–(640,259), replica (64,130)–(638,259), 조립본 (64,131)–(638,260)이다.
- 첫 조립본에서 정수 그리드에 맞춘다는 이유로 달라졌던 전폭 선, 원형 다음 화살표, 큰 장 제목, 30% 수치, 면적 그래프와 09 문의 구성을 다시 복구했다. 페이지 CSS를 추가하지 않고 foundation과 각 요소 CSS의 반복 문법을 고쳤다.
- 03의 원형 진행 화살표가 처음 빠진 원인은 중첩된 `:has()` 선택자가 브라우저에서 무효였기 때문이다. 독립 관계 선택자로 바꿨으며 최종 PNG의 해당 영역에서 흰 원 픽셀 3,285개와 파란 chevron을 확인했다.
- 05의 제목이 일부 큰 비교 이미지 도구 화면에서 비어 보인 현상은 실제 PNG 누락이 아니었다. compare 오른쪽과 standalone은 모든 픽셀이 동일했고 제목 영역에 7,099개의 밝은 픽셀이 있었다. 새 Chromium 3회에서 폰트 loaded, opacity1, visibility visible, 최상단 hit-test H2를 확인했다. 수동 2048px 축소본과 원본 크기 crop에는 제목이 모두 보였다. 이를 브라우저 paint 문제라고 적었던 초기 해석은 철회한다. `headline-investigation.json`에 초기 DOM 조사를 남겼다.
- 사진 카드는 내부 가로 여백8px, 이미지 약212px, 숫자·이름·설명의 공통 기준선을 복구했다. 네 카드의 설명 끝에 생겼던 “요.” 고아줄을 제거했다. 모든 조립본 이미지 자리는 연회색이다.
- hub는 각 방향에서 실제 core에 연결된다. Sankey는 source/target anchor 사이의 대각 리본과 `--v` 두께를 전달한다. radar는 실제 다각형과 방사선, network는 좌표 간 선, treemap은 면적 비율을 그린다. 샘플의 디자인 CSS는 복사하지 않았다.
- 고정된 preview furniture `.frame`와 `small`이 실제 요소를 덮는 문제를 data-el scoped 규칙으로 방어했다. radar/concentric의 size containment가 원 크기를0으로 만들던 문제, nested list의 자연 높이, inline tag 크기, person 학력·경력 숨김을 수정했다.
- 최종 조립 형태를 반영한 라이브러리 검증에서 일반 big+kick headline을 큰 장 제목과 구분하고, 작은 숫자형 세로 steps에서 이름 높이가0이 되지 않도록 압축했다. on+center note의 on-colour도 보완했다.

## 데이터·문구·색 판단

원본의 주요 문구는 읽을 수 있어 임의의 새 사업 문장을 만들지 않았다. “입력해 주세요”는 슬라이드 내용으로만 취급했다. 라이브러리 fixture의 사업 문구는 계약 예시와 별도 한국어 예문이다.

06의 원본에는 축 수치가 없다. 조립본의 `--max:100` 및 `--v:38.16,40.46,43.46,48.59,56.01,69.79`는 이미지상의 점 높이를 백분율로 옮긴 기하 데이터이며 실제 경영 수치가 아니다. 이름·축 노드는 계약 구조로 남기되 원본에 없는 라벨은 빈 값이다. “30% 증가”는 원본 문구다.

컬렉션의 색 리터럴은 kit의 page/ink 미리보기 값뿐이며 나머지는 팔레트 자리다. `assets/deck-style.css`는 색·글꼴·type만 공급한다. 원본 색을 깊게 바꾸어 대비를 맞췄던 최초 조립본은 원본 재현에 맞지 않아 되돌렸다. 02·03의 큰 면뿐 아니라 모든 페이지의 원형 화살표·process 소제목·단계 강조도 원본 파랑을 유지한다. 따라서 source 스타일에서는 작은 글자 대비 경고가 남는다(최신 `audit-reassembled.json`에 원시 수치 기록). 이를 “대비 통과”라고 주장하지 않는다. 라이브러리의 기준 팔레트 검증은 별도로 수행한다.

## 계약·품질 체크

56개 요소, 공유 kit 토큰 전부, foundation2개와 요소별2개 이상 fixture를 포함한다. 모범28개에 포함된 wrapper·작은 배치·기호가 일반 fixture 규칙과 충돌하는 경우에는 사용자가 지정한 동일 마크업·데이터 요구를 우선했다. 비모범 legacy UL/LI는 현행 list 계약과 nested data-el로 바꿨다.

사진 카드의 제목은 설명 길이와 독립된 공유 행에 놓인다. 일반 카드도 name/note 행 높이를 공유하며 중앙 무게를 유지한다. 버튼·표식은 flex/grid 중앙 정렬이다. 선1px·원형 관절·낮은 반경·하단 강조선이라는 한 디자인 문법을56개에 적용했다. 맥락 없는 잎·별 장식을 추가하지 않았다. 좁은 칸의 차트 라벨·도넛 배열·자연 높이 목록·아이콘 비율을 두 모드에서 확인했다.

원시 scrollWidth/scrollHeight 증가는 anchor 연결선·일부 글자 em 상자에서도 발생한다. 실제 clipping·페이지 경계·폰트·대비·숨긴 주요 내용과 함께 판단하며 원시 진단을 삭제하지 않았다. 최신 파일 크기·페이지 수·프로브 수와 진단 요약은 `verification.json`, `audit-*.json`에 있다. 실제 Rhetis intake 실행 파일은 레퍼런스에 없어 정적 계약 확인과 Chromium 실렌더까지 수행했다. 완전한 픽셀 일치를 주장하지 않으며 위 차이를 남긴다.
