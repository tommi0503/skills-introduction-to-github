# Glasspulse 검수 기록

## 범위와 판독

원본은 덱 006의 실제 이미지 18장이다. `index.csv`의 slides=24와 실제 파일 수가 다르므로 존재하지 않는 19–24장을 새로 만들지 않았다. 원본의 `000억`, `00%`, `20XX`, ‘이곳에 설명을 입력해 보세요’는 원본에 실제 있는 문구이며 실적 추정값이 아니다. 판독 불가 문장을 새로 발명한 곳은 없다. 미세한 영문 로고는 단순 도형으로 재작성했다.

원본 폰트 파일이나 편집 가능한 텍스트는 제공되지 않았다. README 안에서 가장 가까운 Pretendard Variable을 실제 로드했으며, 750 굵기와 음수 자간으로 제목의 밀도를 맞췄다. 원본과 자폭·획 끝·기준선이 완전히 같다는 뜻은 아니다.

## 디자인 언어와 컬렉션

키트·foundation과 56개 요소를 새 CSS로 작성했다. 샘플 CSS는 사용하지 않았다. 모범 구성 28개 fixture는 원본 markup과 데이터에 새 data-el 네임스페이스만 적용했다. 나머지는 계약 형태 예시를 바탕으로 최소 두 fixture를 넣었다. 비모범 fixture의 top grid를 12×6으로 정규화했고, 중첩 list/tag에는 각 data-el을 부여했다. singleton 원본의 두 번째 fixture는 긴 이름 또는 멤버 수를 바꾸었다.

수치/텍스트의 단일 강조, 2px 윤곽, 28/18px 모서리, 캡슐 라벨, 바닥 쪽 옅은 면을 56개에 공통 적용했다. `tone-1`은 주 강조 윤곽, tone-2…4는 각 순위의 soft 바닥면, tone-5는 무채색 면이다. 라이트/다크는 계약 기준 팔레트로 검수했다. 기준 팔레트의 원색은 작은 글자에서 대비가 부족해 텍스트에 깊이 7을 사용하고, 강조 채움 위에서는 on 색을 썼다.

요소별 라이트·다크 시트 PNG는 각 요소 폴더마다 한 장이며, 복수 fixture를 한 이미지에 모았다. 각 fixture를 1280×720으로 렌더한 전체 PDF도 제공한다. PDF는 원본 PNG의 픽셀을 리샘플링하지 않고 deflate로 무손실 압축했다.

## 수정한 품질 문제

- 작은 callout의 글자 단계를 낮추고 내부 여백을 줄였다.
- 여러 donut의 내부 padding이 원의 폭을 넘던 문제와 타원형 링을 수정했다.
- 카드 이름에는 2줄, note에는 3줄의 역할 공간을 확보해 같은 행에서 시작 높이를 맞췄다. 넓고 낮은 카드에서는 이름/설명을 두 열로 유지한다.
- 4개 목표 카드에서는 kick/이름을 위에, 큰 fig를 아래 오른쪽에 배치한다.
- 영역 차트의 계단형 간극을 plot 높이 계산으로 제거했다. 중첩된 영역의 누적 면 순서를 수정했다.
- radar는 3–8축에 맞는 각도와 값을 계산하며, network는 atan2/hypot으로 네 방향 연결을 그린다.
- 타임라인 alt는 선 위/아래로 교대 배치한다. 100개 waffle 단위는 높이 안에 들어가는 정사각 격자로 바꿨다.
- pill.on의 mark, matrix.on의 kick, 코드 주석과 문자열의 대비쌍을 수정했다.
- nested list에 size containment가 0 높이를 만들던 것을 inline-size containment로 바꿨다.

## 라이브러리 → 재조립

재조립 HTML에는 별도 디자인 CSS를 쓰지 않았다. `library/collection.css`는 컬렉션 CSS를 그대로 연결한 것이다. `source-style.css`는 원본에 가까운 색을 공급하는 host palette와 계약 type scale만 담고 있으며, 컬렉션 디자인 자체에 원본 색을 넣지 않았다. `assets/icons.js`는 비어 있는 Lucide 표기의 circle-check/check를 브라우저에서 채우는 검수용 loader다.

모든 페이지의 .body는 12×6이며 grid-column/grid-row로 배치했다. 06·07쪽의 큰 판은 card.parts 안에 계약 bars/areas와 callout을 중첩하고, 각 data-el을 유지했다. 이를 위해 card CSS에 nested chart의 명시적 단일 열과 행 높이 지원을 추가했다.

초기 조립 검수에서 제목·수치 정규화와 판의 분리를 허용했던 판정은 사용자 지적 뒤 철회했다. 최종본은 원본의 역할과 배치를 측정해 06/07/11의 통합 판, 09의 체크/선택 강조, 10의 칩/화살표/해결책, 12의 한 방향 비교행, 17의 반투명 겹침/점선 연결/원형 강조까지 복구했다.

## 자동 검수 범위

각 페이지의 크기·실제 폰트 로딩·페이지 밖 텍스트 범위를 검사했다. replica 18장, 조립본 18장 모두 1280×720이고 폰트 로딩 실패 및 페이지 밖 텍스트가 없다. `replica/checks.json`, `reassembled/checks.json`에 원시 결과를 남겼다.

요소별 최소 칸 이상~12×6의 정적·브라우저·대비 통합 검수는 주 에이전트의 integration 기록을 함께 따른다. 로컬 전체 fixture 검사에서 scatter 축 라벨의 root 밖 40px는 외부 margin 안에 축을 두는 의도된 배치이며, 실제 slide/slot을 넘지 않는다. 결과가 0이라고 원시 경고를 지우지 않았다.

최종 소스와 마지막 PNG/PDF의 해시 및 ZIP CRC 검사는 `verification.json`으로 남긴다.

## 연결선 기능 최종 수정
flowchart와swimlane의방향클래스가같은가상요소의단일선을덮어쓰면서복수방향분기의한쪽이사라지고화살촉도없던기능오류를수정했다. 방향마다독립색변수와선4개/삼각촉4개배경레이어를사용하여to-r/to-d/to-l/to-u를모두동시에보존한다. 실제예산범위와재고분기의right/down,생산일정반환의left/up,swimlane의전달선을라이트·다크시트에서직접확인했고,임시브라우저사례로4방향동시분기도눈으로확인했다. swimlane의owner명칭이첫node뒤에가려지던문제는예약폭을확보하여복구했다.기하검사는선/화살촉누락을검출하지못하므로이항목은별도시각검수로검증했다.그밖의slideCSS와18장replica/조립/비교PNG는이수정중그대로보존했고해시일치로확인했다.

마지막 계약 선택자 정리에서는 추가 layout class를 제거하고 기존 head/body/stack/group 및 요소의 계약 구조를 읽는 선택자로 치환했다. 새 디자인 변경은 없으며, 조립18장·비교18장·라이브러리114장 PNG를 다시 렌더해 치환 전 SHA256과150장 모두 동일함을 확인했다. foundation 설명도 추가 class 안내 대신 계약 구조에 따른 배치 설명으로 바꿨다.


## 실제 데이터와 변형 기능 검수
최종 연결선 검수에서 발견한 기능 오류는 장식 잔차로 분류하지 않고 수정했다. sparkline 기본형은 값의 실제 좌표를 잇는 24점 미니 선으로, bars 변형은 하단 기준 막대로 분리했다. slope는 두 시점의 값에 따라 각 축의 세로 위치를 계산하고, dumbbell은 같은 행에서 두 값의 가로 위치와 연결 길이를 계산한다. 브라우저가 계산한 각 끝점과 기대 데이터 좌표를 비교하여 검증하며 `library/functional-audit.json`에 남겼다.
면적 차트의 4개 모범 fixture에서 면과 연속선이 사라지던 원인은 원본의 5점/이름 있는 소형 plot 규칙이 다른 데이터에도 적용된 것이었다. 해당 원본 구조 조건을 명확히 하고 일반 모범 fixture의 전체 plot 높이를 복원했다. 원본 18장 조립본과 비교본 18장은 이 수정 전후 SHA256이 36장 모두 동일하다.
bullet은 선택적인 low/high 정성 구간을 3개 중립 면으로 표시하고, 실제 값은 가운데 얇은 강조 막대, 목표는 수직선으로 겹쳐 그린다. 누적 막대는 각 시리즈의 tone을 구분하며 수평 100% 변형과 세로 실제 수치 사례를 함께 제공한다. 레이더 범례의 겹침, 작은 treemap 타일의 이름/수치 겹침, 저울 기울기에 반응하지 않던 양쪽 판의 높이도 보완했다.
미니 요소는 큰 셀에서만 통과시키지 않고 sparkline 2×1, slope 6×3/8×4, bullet 4×1/8×4부터 실제 브라우저로 검수했다. 변경 후 전체 128개 요소 fixture의 2,404개 그리드/모드 상태에서 글자 경계 초과 0건을 확인했다.

연결형 9개 요소도 최신 소스의 각 fixture를 두 모드에서 따로 열어 확인했다. sankey의 두께는 source의 점유율에 비례하며 각 분기까지 실제 연결한다. mindmap과 hub의 중심 연결, cycle의 폐순환과 촉, journey의 mood/next 선, waterfall의 연속 단계 연결, hierarchy의 trunk, decision-tree의 중첩 분기, concentric의 바깥/안쪽 집합 설명을 복구했다.
마지막 전체 교차검수에서는 avatar의 타원을 원으로, calendar의 모든 day 셀을 정사각으로, 3집합 venn을 실제 삼중 교집합이 생기는 원 배치로 수정했다. 원본 17쪽의 가로 겹침 원은 core가 없는 계약 구조를 유지하여 그대로 보존했다. avatar의 원형, 달력의 가로세로 일치, venn core 중심이 모든 집합 안에 있는지, 저울 두 판이 반대 높이로 움직이는지도 실제 DOM 좌표로 검증했다.
기하·대비 자동 검사만으로 선/면/촉의 존재를 보증할 수 없음을 확인했으므로 연결형 요소는 최종 PNG의 시각 확인과 데이터 좌표 검사를 함께 적용했다. 확정된 기능 오류는 모두 반영했으며, 마지막 소스는 정적 계약 검사 0오류/0경고, 2,404개 그리드 상태 경계 초과 0건, 두 모드 대비 의심 0건, chip26개 중심 검토 후보 0건을 통과했다.

퍼널은 stage의 최소 폭22%가 작은 데이터의 면적을 왜곡하던 기능 오류를 수정했다. stage는 전체 폭의 라벨 축으로 유지하고 실제 면은 padding/border가 없는 중앙 pseudo-element의 v% 폭으로만 그린다. 윤곽은 inset이므로0값에 별도 최소 폭이 생기지 않는다. 0·1·5·10·21·100%를 두 모드에서 주입해 기대 폭과 실제 면의 계산 폭이 일치하며 border/padding이0임을 검사했다. 라벨은 값이 작거나0이어도 중앙 축에서 읽을 수 있다. 이 요소는 원본18장에 사용되지 않아 원본 조립 모양은 유지된다.

최종 계약 마크업 정리에서는15쪽의 overview 문구를 별도 role 클래스에서 기존 name의 small로 옮겼다. 절대 위치·글꼴·굵기를 동일하게 유지하여 조립18장과 비교18장 PNG는 이전 SHA256과 모두 동일하다. waffle의4px 모서리도 기존 kit의18px radius-sm에서 계산하도록 정리해 공유 토큰을 따르면서 모양을 유지했다.
