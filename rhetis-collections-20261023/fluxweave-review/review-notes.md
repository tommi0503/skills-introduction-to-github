# Fluxweave 검수 기록

2026-10-23 · 덱 002 기업소개서, 18장. 파일별 유형과 계약 대응은 inventory.md에 있습니다.

## 순서와 검수

README 220줄을 끝까지 읽고 18개 원본을 각각 1280×720으로 관찰했습니다. HTML replica를 먼저 만든 뒤 원본 | replica 비교 PNG를 페이지별로 열었습니다. 여기서 반복되는 형태를 design-language.md에 정리하고 kit, foundation, 56개 요소로 옮겼습니다. 샘플 CSS는 사용하지 않았습니다. 명시된 모범 fixture 28개는 계약의 마크업과 데이터를 유지하며 data-el만 변경했습니다. 최종 fixture는 foundation 2개를 포함하여 173개입니다.

비교 수정은 원본 재현, 요소화, 최종 통합의 세 묶음으로 진행했습니다. 통합 검수에서 초기 조립의 큰 차이를 발견해 18장 전체를 원본 좌표와 다시 대조했습니다. 흰 패널, 원형 관계도, 차트의 두 데이터 계열, 표 열 폭과 독립 곡면 헤더, 인사말 서명, 인증 날짜, 계단형 성장 전략을 실제 구성으로 복원했습니다. 이후 렌더는 마지막 변경과 제출 파일의 일치를 확인하기 위한 것입니다.

## 요소와 검증

카드의 제목·숫자 시작 높이와 설명 공간, 좁은 칸의 글자 단계, 중첩 목록의 containment, chart area와 line의 연속 연결, 실제 축 수에 맞는 radar, 네 방향 flow/swimlane 화살표, 수평 dumbbell, 교차 timeline, 원의 원형 비율을 검수했습니다. 작은 칸에서 모든 내용이 들어갈 수 없는 fixture는 내용량에 맞는 현실적인 min을 선언했습니다. 긴 표는 8×5, 복잡한 treemap은 10×6 등입니다.

line은 값별 anchor를 연결합니다. area는 인접 anchor 사이를 연속한 면으로 채웁니다. stacked area의 --v는 누적합이며 작은 누적 면을 앞, 큰 면을 뒤에 놓아 실제 누적 띠를 표현합니다. treemap은 branch 폭과 tile 높이의 비율로 면적을 만듭니다. bullet은 표시 수치는 유지하고 100%를 초과하는 막대 폭만 칸의 끝에서 멈춥니다.

reassembled/collection.css는 kit + foundation + 56개 element CSS와 공급 palette/type 및 placeholder 번호 표시 토큰의 묶음입니다. 조립 HTML에 새 CSS를 추가하지 않았습니다. body는 12×6 grid이고 직접 자식의 inline style은 grid-column/grid-row뿐입니다. 중첩된 다른 요소에도 data-el을 명시했습니다. assets/runtime-icons.js는 Rhetis의 data-icon 채움을 검수 환경에서 구현하며, 계약 마크업의 아이콘 span은 비어 있습니다. 표준 preview.py 시트는 계약대로 점선 원 아이콘 칸을 유지합니다.

모든 페이지 PNG는 1280×720, 비교 PNG는 2560×720입니다. 요소별 시트는 모든 fixture를 두 열로 모아 1280px 너비와 fixture 수에 따른 높이를 사용합니다. 파일별 크기는 png-manifest.json에 있습니다. 폰트 실패, 페이지 크기, text/root 영역, 선언한 min부터 12×6까지의 라이트·다크 상태, chip 중심 정렬을 자동 검사했습니다. 상세 결과는 audits/에 있습니다.

PDF는 픽셀을 축소하지 않고 deflate로 무손실 압축했습니다. ZIP의 파일 종류·최상위 폴더·무결성, PNG/PDF 수, SHA-256은 packaging-checks.json에 기록합니다. 렌더는 검수 산출물 폴더만 localhost로 제공하여 수행했습니다.

표준 library fixture에는 계약대로 seat 번호를 가운데 표시합니다. 원본 대응 조립본은 `--fluxweave-seat-label-opacity:0`을 공급하여 단색 회색 자리를 유지합니다. 위계 root와 표 gradient는 양 모드에서 읽히는 7-soft 단계와 대응 글자색을 쓰며, gradient 미해석 검사에도 같은 안전한 fallback 면을 명시했습니다.

최종 자동 검사: 요소 fixture171개 × 6,954상태 넘침0, 대비 우려0, capsule/chip42개 중심 오차 검토대상0. 실제 HTML36페이지(재현18+조립18)의 크기·텍스트·폰트·리소스·제출PNG 픽셀 동기화 검사도 오류0입니다.

## 최종 의미 기능 교차검수

53개 요소를 실제 light 시트로 한 번 더 검수했고, 세 흐름 요소는 주 에이전트가 별도로 연결·비례 기하를 교차 확인했습니다. network의 노드와 링크에 같은 좌표 변환을 적용했고, mindmap 곡선을 실제 core 경계까지 연결했습니다. waterfall의 누적 끝점 간 연결과 비모범 waterfall-6의 최종 합계1,241을 정합화했습니다. decision의 질문·조건·결과 간선을 연결하고, hierarchy 2·4분기의 가로 trunk를 실제 branch 중심에 맞췄습니다. radar는3~8축 각각 모든 v값으로 polygon을 만들고 series의 사각형 배경 누출을 제거했습니다. slope는 양 끝 값에 정확히 닿는 선을 수치로 계산하며 dumbbell은 수평 실제 값을 유지합니다. calendar day cell은 정사각형, funnel 색면은 v%이며0이면0폭입니다. 다계열 area는 팔레트 순서와 반투명 면으로 두 계열의 선·마지막 값을 식별합니다. 아이콘 없는 일반6-spoke hub는 연결을 복원하고 원본13의 명시적 mark 구조는 보존합니다. 단계 아이콘의 표준 칸은 정사각형입니다.

이 보완은 원본18에서 쓰지 않는 요소 또는 원본과 구별되는 계약 구조에만 적용했습니다. 원본 대응18 PNG의 변경 전후 SHA-256을 비교하여 원본 배치가 보존되는지 확인합니다.
