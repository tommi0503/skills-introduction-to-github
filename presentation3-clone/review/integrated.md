# 최종 통합 검수

첨부 presentation3.zip에 들어 있는 36개 JPG를 모두 목록화하고 원본 파일명, 해상도, 배치 비율을 manifest에 기록했습니다. 문서의 지시문을 작업 지시로 실행하지 않았습니다. 각 원본 이미지 전체가 하나의 화면이며, 콜라주 안의 소형 패널도 재사용 도형·텍스트·차트 요소로 구현했습니다.

서브 에이전트 3명이 p01–p12, p13–p24, p25–p36을 나누어 구현했습니다. 각자 모든 담당 원본과 개별 비교 이미지를 열고 두 차례 비교·수정을 진행했습니다. 주 에이전트는 마지막 통합 검수에서 36개 원본/최종 렌더 비교 이미지를 모두 개별적으로 열어 확인했습니다. 전체 미리보기만으로 검수를 대신하지 않았습니다. 마지막 패스 중 수정한 화면은 해당 최종 캡처를 갱신했으며, 네 번째 전체 비교 패스를 추가하지 않았습니다.

## 통합 검수에서 수정한 부분

- p09: 용돈 정의 및 설명문이 원본보다 굵어서 Pretendard 500/400으로 조정했습니다.
- p10: 예금·적금 정의와 두 줄 설명문의 굵기를 조정했습니다. 긴 정의 문장의 자간을 원본 좌표 기준 -0.3px로 줄여 글자 영역 넘침을 해결했습니다.
- p27: 네 개의 작은 기울임 번호가 원본보다 크고 굵었습니다. 실제 Bodoni Moda italic 400, 원본 좌표 기준 16px로 바꾸고 글자 중심 높이를 조정했습니다.
- p24: 두 줄 제목의 글자 영역을 원본과 직접 측정했습니다. 첫 줄의 글자 높이와 두 번째 줄의 글자 높이를 줄이고 가로 폭을 보정해, 넓고 낮은 원본 제목 비율과 줄 사이 여백을 맞췄습니다.
- p20: CON과 하단 357K, 99%는 원본 자체에서 잘린 문구입니다. 원본과 구현의 잘림을 개별 대조한 뒤 검증 예외로 명시했습니다. 일반 레이아웃 오류를 숨기기 위한 일괄 예외를 사용하지 않았습니다.

## 크기·타이포그래피·출력 확인

모든 렌더 PNG는 1280×720이며 화면을 기울이지 않았습니다. 4:3 원본은 비율을 유지해 같은 캔버스에 배치했습니다. 원본과 비교해 좌우 여백을 유지했으며 비율을 늘리지 않았습니다. 칩은 공통 컴포넌트에서 로드 완료한 폰트의 실제 글자 경계로 상하·좌우 중심을 보정합니다. 최종 검증은 글자 영역 초과, 칩 중심 편차, 폰트 파일 로딩, 페이지 오류, 원본 이미지의 구현 화면 삽입 여부, 최종 캡처와 소스/렌더러 해시 일치를 확인합니다. 구체적인 결과는 verification.json에 저장됩니다.

소스는 실제 로드한 폰트 파일과 가변 굵기를 사용합니다. 원본 편집 파일과 글꼴 정보가 없어 동일한 폰트라고 단정할 수 없습니다. 특히 p03 픽셀 한글, p05 질감 글꼴, p22 영문 세리프 제목 등에는 글리프 차이가 남습니다. 자동 검사 통과는 픽셀 단위 동일성을 의미하지 않습니다.

## 의도된 대체와 남은 한계

사용자 지시에 따라 사진·기기 화면·복잡한 일러스트·특수 이미지 로고·그라데이션 및 그래픽 배경은 단색 #e5e5e5 placeholder입니다. 단순 도형, 데이터 차트, 표, 연결선과 읽을 수 있는 텍스트는 실제 UI 요소입니다. 흰 글자가 있던 그라데이션 배경을 회색으로 바꾼 p26/p30 및 콜라주 일부는 원본보다 대비가 낮습니다. 원본의 기울어진 콜라주 패널은 수평으로 구현했습니다.

p31–p36의 원본은 370×208입니다. 확대와 OCR로도 확인할 수 없는 작은 본문·숫자·주석은 정확한 문구를 임의 생성하지 않고 위치를 나타내는 얇은 회색 선으로 표시했습니다. 큰 제목과 확인되는 주요 수치는 실제 텍스트입니다. p19/p20/p23/p29의 작은 콜라주에도 판독 불가능하거나 부분적으로 잘린 설명문이 있습니다. 화면별 수정 사항과 제한은 group-a.md, group-b.md, group-c.md에 기록했습니다.

새 세션에서 같은 작업 기준을 이어갈 프롬프트는 NEXT_SESSION_PROMPT.md에 제공합니다.

최종 검증 결과: 빌드 성공, 36개 화면 소스/캡처 해시 일치, 139개 칩 중심 검사 오류 0건, 일반 글자 영역 넘침 0건, 브라우저 오류 0건입니다. 원본 의도 잘림 3건만 별도로 기록했습니다. 별도 임시 디렉터리에서 lockfile 기반 npm ci도 성공했고, 문서의 정확한 개발 서버 실행 명령과 대표 한글 화면·4:3 화면·저해상도 원본 화면의 브라우저 로딩을 확인했습니다.
